# TG 快取 v0.18.4

## 任务中心响应速度

- 任务中心使用稳定任务 ID 和批量聚合快照；普通进度在固定 500 ms 窗口内合并，只更新实际变化的任务行。
- 任务名称筛选采用 150 ms 防抖，暂停、继续、失败、完成、归档、恢复和优先级变化仍会立即刷新。
- 任务中心可见时每 5 秒执行一次后台完整校准，修复遗漏事件；离开任务中心后停止周期校准，返回时立即校准。
- 媒体明细每页最多 500 条，使用键集分页追加；可见和已选媒体按 ID 批量更新，不为未加载媒体创建 Qt 行。
- 账号、任务和媒体加载都受代次保护；旧结果会被完整取回但不会覆盖当前界面。

## 合成响应门禁

- 固定合成门禁覆盖 10,000 个任务、50,000 个媒体、50 ms 慢仓储、5 ms 窗口心跳和 500 次连续进度事件。
- 七轮基准要求任务初始加载、筛选、单行更新和媒体首个分页中位数均不超过 100 ms，最大事件循环间隙不超过 20 ms。
- 基准同时要求初始加载后模型重置为 0，500 次进度事件只形成 1 个 dirty 批次。

## 兼容性

- 不增加业务字段迁移，不改变已有任务、下载目录、命名模板、账号会话或配置；升级后可继续现有任务。
- 分页索引为幂等兼容索引，不改变数据库 schema 版本；创建失败时保留正确查询能力，并仅在下载空闲时重试。
- 不增加系统权限、后台服务或新的联网行为。
- 强制终止不改变既有下载持久化语义：数据库显示进度仍受固定写入窗口约束，续传仍以同目录 `.part` 文件长度为准。

## 隐私边界

- 响应测试和基准只使用临时目录、固定合成任务、合成媒体及人工延迟，不读取真实数据、账号、会话、消息、文件名、下载路径或凭据，也不连接 Telegram。
- 日志和诊断只记录动作类型、数量、耗时、代次及错误类别，不记录任务标题、来源、媒体名称或路径。

## 发布边界

- 当前说明对应 v0.18.4 本地候选；本任务不合并主分支、不创建标签、不推送，也不发布在线更新。

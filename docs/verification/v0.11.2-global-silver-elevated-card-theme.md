## Real Qt window review

The application was shown and processed through the native Windows Qt event loop.
Navigation used real QTest.mouseClick events before each page capture.

Pages inspected at both 1180 × 720 and 1280 × 780:

- task center;
- account content;
- automatic subscriptions;
- health diagnostics.

Dialogs shown and inspected:

- login (620 × 720);
- settings (620 × 700);
- subscription editor (620 × 520);
- media preview (780 × 620);
- signed update (560 × 520).

Thirteen fresh renders were checked. The review confirmed:

- no dark-theme remnants;
- a visible white-to-silver gradient on the app canvas and cards;
- major shadows visibly stronger than nested shadows;
- no clipped, doubled, or blackened card edges;
- no text overflow, button clipping, or compressed action rows;
- task-center batch actions remain inside the queue card at minimum size;
- account-content fixed columns and checkbox layout remain intact;
- subscription history/probe panels and diagnostic actions remain visible;
- every custom dialog has one major elevated surface.

Measured rendered pixels after the top-level canvas regression fix:

- main canvas: rgba(246, 248, 251, 255);
- task card sample: rgba(252, 253, 254, 255);
- dialog outer canvas: rgba(247, 249, 252, 255);
- dialog surface sample: rgba(254, 254, 254, 255).

Windows Graphics Capture could not access the monitor in this environment
(0x80070005, followed by 0x80070057). The review therefore used Qt's own
QWidget.grab() after showing each real widget and settling the event loop. The
screenshots were QA-only files under ignored .build-temp storage and are not
tracked. Live authenticated Telegram content was not loaded; populated-state
behavior remains covered by the existing model, layout, selection, and action
tests.

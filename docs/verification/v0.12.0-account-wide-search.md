## 合并审查与集成修复

功能分支合入最新远端基线后完成逐文件冲突审查，同时保留 v0.11.2 的整格勾选、稳定列宽、白色卡片交互和本次新增的来源列。

审查发现并修复两项集成问题：

1. 新增来源列使最低窗口宽度下的结果表出现水平滚动。根因是固定列占满视口后，Qt 仍要求伸缩摘要列保留默认最小宽度。来源列改为可省略的 92 像素固定列，摘要列在最低窗口下可缩至 40 像素，宽窗口下继续自动伸展；来源与摘要均保留完整悬停提示。
2. 全账号搜索把内容目录升级到 schema 4，而健康诊断仍独立硬编码 schema 3。目录模块现在提供唯一的 `CATALOG_SCHEMA_VERSION`，初始化与健康诊断共同引用，避免后续迁移再次漂移。

发布版本切换还移除了自检与主窗口测试中的旧版号重复硬编码；精确版本由打包契约约束，运行时绑定测试直接比较包版本。

## 隐私与账号边界

- `catalog.py` 与日志模块中未发现 API Hash、StringSession 或代理密码持久化路径。
- 目录数据库只保存匹配媒体所需的标识、来源、筛选条件、游标和消息摘要，不保存完整聊天正文。
- 全账号搜索只能读取当前账号仍有权访问的 Telegram 云端消息；秘密聊天、已删除、已撤回或无权访问的历史不可搜索。
- 本机项目根目录和功能工作树均没有可用的 Telegram 凭据或会话文件，因此本轮发布前无法执行真实账号人工冒烟。该限制不以模拟结果冒充通过，正式发布判断以协议单测、持久化端到端测试和打包自检为依据。

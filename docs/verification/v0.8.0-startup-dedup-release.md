# TelegramDownloader v0.8.0 启动、去重与发布验收记录

## 结论

v0.8.0 本地候选版通过三轮完整自动化验证、真实已保存会话与真实媒体下载、两档窗口视觉检查、便携包自检和安装器冒烟测试。普通链接、账号内容搜索与自动订阅现在统一按 Telegram 媒体身份去重；所有受管数据路径继续限制在应用目录。

## 根因与修复

| 问题 | 根因 | 修复与防回归 |
| --- | --- | --- |
| 冷启动长时间没有可见反馈 | 完整应用模块导入、Qt 主窗口构造和本地服务恢复都发生在首个窗口显示之前 | 入口先创建轻量启动提示，分阶段更新状态；主窗口在账号和任务恢复前显示。启动提示显式加载 Windows 中文字体，并有可见性、关闭和异常路径测试。 |
| 普通链接可能重复创建任务或文件 | 普通链接预览未查询全局媒体键，确认时使用非去重写入；确认期间的并发变化会触发唯一键错误 | 预览前过滤已有媒体，确认时再次使用原子去重事务；界面报告实际加入和跳过数量。相册、搜索和订阅使用同一媒体键边界。 |
| 大任务状态切换产生多余数据库读取 | 每个媒体状态变化都会读取任务的全部媒体再查找一个条目 | 调度器改为按媒体条目 ID 直接读取，测试确认成功任务只进行一次队列列表读取。 |
| 启动画面离屏验收出现中文方框 | 启动画面早于主界面字体初始化 | 提前复用项目的 CJK 字体加载器，同时设置绘制字体和状态文字字体；重新截图确认中文完整。 |

## 已知边界

- Telegram 的访问权限、内容保护、已删除消息和服务端频率限制仍然有效，程序不会绕过这些限制。
- 首次启动耗时受 Windows 安全扫描、磁盘缓存和机器性能影响；v0.8.0 的保证是尽早显示可靠状态，而不是承诺固定启动秒数。
- 未购买商业 Authenticode 证书，Windows 可能显示“未知发布者”；应用在线更新仍强制 Ed25519 清单签名与 SHA-256 资产校验。

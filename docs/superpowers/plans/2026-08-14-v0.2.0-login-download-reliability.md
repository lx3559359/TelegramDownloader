# TelegramDownloader v0.2.0 Login and Download Reliability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver v0.2.0 with QR-first Telegram login, reliable private `t.me/c/...` resolution after restart, persistent safe failure feedback, and verified portable/installer updates published to GitHub and ModelScope.

**Architecture:** Keep Telethon behind `TelegramGateway`, extend it with QR-token primitives and a dialog-list fallback for private numeric peers that are absent from `StringSession`'s in-memory entity cache. Keep QR rendering in a small UI-only module, keep login task ownership in `AppController`, and surface safe failures through both a persistent status message and the task table while recording redacted diagnostics in the project-local rotating log. Execute every behavior change as an isolated red-green-refactor cycle, then run source, packaged, installer, update, secret-scan, and remote-hash loops before release.

**Tech Stack:** Python 3.12, PySide6 6.11.1, Telethon 1.44.0, qasync 0.28.0, qrcode 8.2, SQLite, Windows DPAPI, pytest/pytest-asyncio/pytest-qt, Ruff, PyInstaller onedir, Inno Setup 7 x64, Ed25519 signed dual-source updater

`begin_qr_login(refresh=False)` cancels and awaits the previous wait task, creates or refreshes the token, displays it, increments the generation, and starts exactly one `_wait_for_qr(generation)` task. `_wait_for_qr`:

- on `TimeoutError` refreshes in the same task and continues waiting;

# 下载位置、手动更新与界面可读性优化设计

状态：用户已确认“原位增强”方案。本设计覆盖五项改进：系统目录选择、复选框勾号、托盘菜单配色、完全手动更新和搜索摘要完整换行。

## 1. 背景

当前“下载路径”页只有目录模板和文件名模板。用户需要理解模板语法并手动输入，不能通过 Windows 文件夹选择器决定媒体的存储根目录。所有下载目标也被 `PortablePaths.guard()` 限制在应用目录内。

全局样式只把选中的复选框填充为青色，没有绘制勾号。托盘菜单没有独立样式，在 Windows 深色系统菜单与应用浅色主题组合下会出现黑底深色文字。应用默认在启动后检查更新，设置页只有自动检查开关，没有明确的手动入口。账号内容搜索表则关闭了自动换行并启用右侧省略，长摘要不能完整阅读。

本设计是对以下旧规格的定向覆盖：

- 覆盖 `2026-08-22-download-path-naming-templates-design.md` 中“下载目录固定在项目内”的限制，但保留其模板语法和路径安全规则；
- 覆盖 `2026-08-22-tray-background-notifications-scheduling-design.md` 中前台或后台启动自动检查更新的行为；
- 覆盖 `2026-08-22-account-content-results-correctness-design.md` 中摘要单行省略以及只局部修正复选框的范围。

未被本设计明确覆盖的旧规格继续有效。

## 2. 目标

- 通过系统文件夹选择器设置媒体下载根目录，不要求用户手动输入绝对路径。
- 保留现有目录与文件名模板，使新根目录仍可按来源、日期和媒体类型组织文件。
- 所有普通复选框在选中时显示清晰的白色勾号，并具备可辨认的未选中、焦点和禁用状态。
- 托盘右键菜单始终使用与应用一致的浅色配色，文字、悬停项和禁用项均清晰可读。
- 取消所有启动时更新检查；只有用户点击“检查更新”后才访问更新源。
- 搜索摘要在表格中完整换行，并维持大量搜索结果下的滚动和缩放响应速度。
- 完成后执行三轮相互独立的自检。

## 3. 非目标

- 不迁移、移动或重命名已经下载的文件。
- 不改变已经创建任务的持久化目标路径。
- 不取消目录模板、文件名模板或现有安全化规则。
- 不允许配置、数据库、会话、缓存、诊断或更新文件迁出应用目录。
- 不增加后台自动更新、静默下载、静默安装或定时更新检查。
- 不重做搜索结果为卡片列表，也不改变搜索、缩略图、选择和入队语义。
- 本轮不发布新版本；构建或发布需由用户另行明确要求。

## 4. 方案与决策

### 方案 A：原位增强（采用）

保留现有设置页签，在“下载路径”页顶部新增根目录选择器，模板继续显示在下方；在“常规”页用手动检查按钮替换自动检查开关。复选框和托盘菜单由共享主题层修正，搜索表只增加专用换行与行高计算。

该方案学习成本最低，能保留已经发布的命名模板，且改动范围集中在现有组件边界内。

### 方案 B：设置页卡片化重构

把存储、文件组织和应用更新改成独立卡片。信息层级更清楚，但会扩大设置窗口、滚动范围和回归面，不适合本轮缺陷修复。

### 方案 C：固定目录极简模式

用系统目录选择完全替代模板。界面最简单，但会移除已发布的灵活命名能力，与现有高级用户需求冲突。

## 5. 下载位置设计

### 5.1 设置界面

“下载路径”页从上到下显示：

1. “下载根目录”：只读文本框，展示规范化后的绝对路径；
2. “浏览…”：调用 `QFileDialog.getExistingDirectory()`，允许用户在系统界面中选择或创建文件夹；
3. “恢复默认”：恢复为应用目录下的 `downloads`；
4. “目录组织模板（高级）”和“文件名模板”：保留现有可编辑预设；
5. 路径预览：使用当前选择的根目录和模板显示最终示例。

只读文本框不能粘贴或键入路径。取消文件夹对话框不改变当前值。选择新目录只更新对话框草稿，点击“保存”且验证成功后才应用。说明文字明确区分“根目录”和“根目录内的组织模板”。

侧栏原有“数据不离开应用目录”改为“应用数据保存在本机，媒体目录可自定义”，避免与新行为冲突。

### 5.2 配置模型与兼容

新增独立 `DownloadStorageSettings`：

- `root`：字符串；空字符串表示默认的 `<应用目录>/downloads`；
- `trusted_roots`：内部使用的历史根目录元组，不在设置界面显示。

`AppSettings.download_storage` 持有该对象，`download_naming` 继续只负责相对目录和文件名模板。旧设置缺少 `download_storage` 时使用默认目录，行为与 v0.15.0 一致。

移除 `check_updates_on_startup` 的运行时含义。加载旧设置时显式丢弃该字段，无论旧值为真或假，升级后均不会自动检查更新。保存后的设置文件不再写出该字段。

### 5.3 路径策略

应用内部路径和媒体路径使用两个明确边界：

- `PortablePaths.guard()` 继续只允许应用根目录下的配置、数据库、缓存、日志、诊断和更新文件；
- 新增 `DownloadPathPolicy`，只负责默认根目录、当前媒体根目录和受信历史根目录内的媒体文件。

根目录保存前执行以下验证：

- 必须是规范化后的绝对路径；
- 不得是盘符根目录、UNC 共享根目录或应用根目录本身；
- 不得指向应用内部的 `data`、缓存、更新、诊断目录或其子目录；
- 目录不存在时由系统文件夹选择器创建，保存阶段不接受凭空输入的不存在路径；
- 使用随机名称创建、刷新并删除一个零字节探测文件，确认目录当前可写；
- 探测失败时不保存设置、不切换运行时根目录，并显示具体可操作错误。

目录和文件名模板仍只生成相对路径。渲染后必须通过 `DownloadPathPolicy.guard()`，确保 `..`、绝对路径、符号链接解析或其他路径注入不能逃离目标根目录。

Windows 盘符目录、可移动磁盘目录和当前可写的 UNC 子目录使用同一验证规则。应用不承诺离线网络目录或拔出的可移动磁盘可继续下载；运行时不可用时不得静默回退到默认目录。

### 5.4 生命周期与旧任务

- 新任务使用保存时的当前根目录和命名模板生成目标路径。
- 已创建任务继续使用数据库中的原目标路径，修改设置不会移动文件或改写断点续传位置。
- 每次切换根目录时，旧根目录加入 `trusted_roots`。下载策略只允许受信根目录内的旧任务继续运行。
- 本轮不自动移除 `trusted_roots` 中的历史记录，避免归档任务或完整性记录失去路径权限；路径按 Windows 大小写不敏感语义规范化并去重。任何情况下都不删除历史目录或文件。
- 重启后，默认根目录、当前根目录和受信历史根目录共同恢复，因此旧任务可以安全续传。
- 当前根目录不可用时，应用本身正常启动；新预检和新任务创建被阻止，已有受影响任务保持可恢复状态，并显示“下载目录不可用”。用户重新连接磁盘或在设置中选择新目录后可继续。

Planner 增加原子 `configure_downloads(root, naming)`，避免根目录和模板分两步更新。下载器、任务目录打开、文件完整性、存储扫描和手动清理共同依赖 `DownloadPathPolicy`，不能继续把媒体路径交给应用内部路径守卫。

托盘“打开下载目录”打开当前媒体根目录；任务“打开目录”根据任务实际目标计算公共父目录，并先通过受信根目录验证。

## 6. 复选框视觉设计

应用级主题安装一个轻量 `QProxyStyle`，在 Qt 完成复选框 indicator 的基础绘制后，为选中状态绘制抗锯齿白色勾号。这样不依赖外部图片路径，在源码运行、冻结包和安装包中行为一致。

视觉状态固定为：

- 未选中：18×18 像素、白底、灰蓝边框、5 像素圆角；
- 选中：品牌青色 `#17A8C2` 背景和白色勾号；
- 键盘焦点：indicator 外显示柔和青色焦点环；
- 禁用：浅灰背景、边框和勾号，仍能区分选中与未选中。

样式应用于设置、账号内容筛选、任务预检、自动订阅和维护中心的普通 `QCheckBox`。表格中的可勾选项继续由项目委托处理，但共享相同的颜色和勾号几何。文字点击、空格切换、禁用逻辑和可访问性角色保持不变。

## 7. 托盘菜单设计

`QtTrayAdapter` 在创建 `QMenu` 时直接设置专用对象名、调色板和样式表，不能依赖主窗口样式继承或 Windows 当前菜单主题。

固定状态为：

- 背景：白色；
- 普通文字：深灰蓝 `#22394A`；
- 悬停/选中：浅青背景和深青文字；
- 禁用项：浅灰文字；
- 分隔线：浅灰蓝；
- 菜单边框、圆角、内边距与主界面白色卡片一致。

样式只作用于本应用托盘菜单，不修改系统全局主题。菜单动作、快捷行为和启用状态不变。Windows 浅色和深色系统主题下都必须保持可读。

## 8. 完全手动更新设计

### 8.1 用户流程

“设置—常规”中的自动更新复选框改为独立更新区域：显示当前版本、状态文字和“检查更新”按钮。

1. 打开应用时不访问更新源，前台启动、后台启动和托盘恢复均相同。
2. 用户点击“检查更新”，按钮变为“正在检查…”并禁用。
3. 同一时间只允许一个检查任务；重复请求复用当前任务。
4. 没有更新时就地显示“当前已是最新正式版”。
5. 更新源不可用、签名或双源结果不一致时显示安全错误，不下载任何文件。
6. 发现更新时显示现有签名更新对话框，包含版本和更新说明。
7. 只有用户点击“下载并安装”后才下载、校验、启动替换助手并退出应用；关闭或取消对话框不产生下载。

更新检查与设置保存相互独立。用户无需先保存其他设置即可检查版本。检查完成、失败或取消后按钮恢复可用。设置对话框打开时，更新确认框以正确的活动窗口为父级，不能隐藏在模态设置窗口之后。

### 8.2 组件边界

- Controller 不再在 `start()` 中读取自动检查设置或调用更新协调器。
- 更新协调器提供语义明确的交互式检查结果：`no-update`、`blocked`、`declined`、`launched`；现有下载、签名校验和替换协议保持不变。
- 设置对话框只发出 `update_check_requested` 并呈现忙碌/结果状态，不直接访问网络或更新文件。
- App 层连接异步动作、更新提示和 UI 状态，继续使用现有异步动作防重与错误边界。
- 通知中的“发现更新”路由仍可导航到手动检查入口，但通知本身不得自动开始检查。

## 9. 搜索摘要完整换行

账号内容搜索结果保留当前列结构、88×60 缩略图、78 像素最低行高和无横向滚动条约束。摘要列修改为：

- `wordWrap = true`；
- `textElideMode = ElideNone`；
- 使用专用 `WrappedSummaryDelegate` 计算和绘制完整文本；
- 行高取缩略图最低高度与摘要实际布局高度的较大值。

单条摘要当前最多 500 个字符，必须全部显示，不设置三行或四行截断。日期、类型、大小、状态等元数据列继续使用固定宽度，摘要列使用剩余宽度。

为避免 500–10,000 条结果一次性测量造成卡顿：

- 新增结果时只测量新增行和当前可见行；
- 滚动到尚未测量的行时再计算并缓存高度；
- 摘要列宽变化时使缓存失效，并通过单次短延迟定时器合并连续窗口缩放事件；
- 模型重置、字体或 DPI 变化时清空缓存；
- 缩略图懒加载、渐进搜索批次和双击预览不触发全表重复测量。

## 10. 错误处理

- 文件夹选择取消：保持原值，不显示错误。
- 根目录失去权限或离线：阻止新目标创建，已有任务保持可恢复，不改写到其他目录。
- 写入探测清理失败：设置保存失败并报告路径，不遗留已知探测文件。
- 旧任务目标不在任何受信根目录：拒绝下载或打开，并提示运行路径安全检查，不放宽为任意数据库路径。
- 更新检查失败：保持当前版本正常运行，按钮恢复，错误不触发退出或安装。
- 更新检查任务被设置窗口关闭取消：安全取消 UI 等待；若底层请求已进入不可取消阶段，则结果被丢弃，不弹出孤立窗口。
- 摘要高度计算异常：该行回退为 78 像素并记录错误，不能破坏整个结果页。
- 托盘样式不可用：菜单仍使用显式文字调色板，确保最低可读性。

## 11. 测试设计

### 11.1 下载位置

- 旧设置缺少下载位置时仍使用应用 `downloads`。
- 文件夹浏览取消、选择、恢复默认和只读文本框行为均有 UI 测试。
- 保存前覆盖绝对路径、盘符根、UNC 根、应用内部数据目录、不可写目录和成功写入探测。
- 当前根目录与模板原子应用；新任务使用新根，旧任务路径不变。
- 切换多个根目录并重启后，历史任务仍可续传；未知根目录被守卫拒绝。
- 下载器、打开目录、完整性扫描和存储维护使用同一个媒体路径策略。
- 符号链接、`..`、保留名和超长模板的现有安全测试继续通过。

### 11.2 复选框与托盘

- 离屏渲染未选中、选中、焦点、禁用四种复选框，验证选中 indicator 内存在白色勾号而不是纯色块。
- 设置、账号内容和自动订阅页面均安装共享样式；鼠标和空格切换测试保持通过。
- 托盘菜单在模拟浅色和深色系统调色板下，普通、悬停和禁用文字与背景均使用显式应用颜色。
- 托盘动作信号和启用状态回归测试保持不变。

### 11.3 手动更新

- 前台和 `--background` 启动均不调用更新源。
- 旧设置中的 `check_updates_on_startup=true` 被忽略并在下次保存后移除。
- 点击按钮只启动一个检查；忙碌状态、最新、阻止、失败、取消和发现更新均恢复正确 UI。
- 发现更新但取消时不下载；明确接受后继续通过现有签名、哈希、替换和回滚测试。
- 设置窗口打开时更新确认框不会被模态层级遮挡。

### 11.4 搜索换行与性能

- 长摘要不使用省略，行高大于 78 像素且完整文本布局在单元格内。
- 窗口缩放后高度缓存失效并重新计算，表格仍无横向滚动条。
- 10,000 条构造结果不会在初次显示时同步测量全部行；只处理新增或可见范围。
- 滚动、渐进加载、缩略图更新、选择、全选、反选、入队和双击预览回归通过。

## 12. 三轮自检

实现完成后按顺序执行三轮独立验证，每轮都从干净的新命令输出取证：

1. **定向自检**：运行设置、路径策略、更新、主题、托盘和搜索结果相关测试，检查五项验收行为。
2. **完整工程自检**：运行完整 pytest、Ruff、源码编译和项目已有静态/契约检查，确认没有跨模块回归。
3. **Windows 成品自检**：构建正式程序，执行启动、设置目录、复选框、托盘菜单、手动更新和长摘要冒烟；至少在 Windows 浅色与深色主题、100% 与 125% 缩放下检查关键界面。

任一轮失败都先修复，再从该轮重新开始；不能用前一轮旧结果代替。发布不属于本设计，除非用户后续明确授权。

## 13. 验收标准

1. 用户可以通过 Windows 文件夹选择器设置任意当前可写的媒体目录，且不能手动输入绝对路径。
2. 配置、数据库、会话、缓存和更新仍只保存在应用目录。
3. 新任务使用新目录，旧任务不迁移且能在受信历史目录中续传。
4. 所有普通复选框选中时显示清晰白色勾号，未选中、焦点和禁用状态可辨认。
5. 托盘菜单在 Windows 浅色和深色主题下文字均清楚可读。
6. 应用启动不访问更新源；只有点击“检查更新”才检查，只有点击“下载并安装”才改变程序文件。
7. 搜索摘要完整自动换行，元数据列不被挤压，窗口缩放和大量结果滚动保持响应。
8. 三轮自检全部通过，并分别保留可核对的新鲜输出。

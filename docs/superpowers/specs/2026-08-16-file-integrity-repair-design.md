# TelegramDownloader v0.9.0 文件完整性与精准修复设计

## 背景与目标

v0.8.0 会在下载完成时核对已知文件大小，并把 `.part` 原子替换为最终文件；但完成后只在“打开文件”时检查文件是否存在。用户移动、截断或修改文件后，任务仍可能显示完成；同尺寸损坏无法发现，重试也只能按整个任务执行。

v0.9.0 增加项目内文件完整性基线、后台校验和指定媒体重新下载。成功标准是：

- 新下载完成时自动记录 SHA-256 和校验时间。
- 旧版完成文件首次手动校验时建立基线；已有数据库无损迁移。
- 校验能区分正常、缺失、大小不符和哈希不符，并让任务状态准确反映异常。
- 用户可校验选中的媒体或任务，也可只重新下载指定异常媒体。
- 损坏的现有文件先移动到同目录的冲突安全 `.corrupt` 留档，不静默覆盖或删除。
- 校验与修复均显示进度、支持取消、抑制重复点击，不阻塞 Qt 事件循环。
- 配置、数据库、哈希、临时文件、损坏留档和下载内容继续全部位于应用目录。

## 方案选择

采用持久 SHA-256 与显式后台校验。仅检查存在和大小虽然更快，但无法发现同尺寸损坏；每次启动自动重算全部哈希会拖慢启动并增加磁盘读取。因此新下载自动建立基线，历史文件和后续复查由用户发起，界面显示进度和取消。

批量链接导入与跨群组全局搜索不进入本版。它们提升内容发现效率，但不应与下载可靠性迁移、状态机和修复流程同时扩大范围。

## 数据模型与迁移

`media_items` 幂等新增三个字段：

- `integrity_status TEXT NOT NULL DEFAULT 'unverified'`
- `content_sha256 TEXT`
- `verified_at TEXT`

完整性状态固定为：

- `unverified`：没有可信本地基线，包含所有旧版迁移记录。
- `verified`：当前文件的大小与 SHA-256 均通过。
- `missing`：最终文件不存在。
- `size_mismatch`：实际大小与 Telegram 已知大小不一致。
- `hash_mismatch`：大小正常，但与已保存 SHA-256 不一致。

SHA-256 必须是 64 位小写十六进制；校验时间保存 UTC ISO 8601。异常状态仍保留上一次哈希用于诊断；用户确认修复时才清空旧基线并进入重新下载。旧任务、媒体身份唯一约束、归档和去重记录保持不变。

仓库提供原子方法写入校验成功、写入校验失败、准备指定媒体重下，并根据任务下所有媒体状态重新计算任务状态。校验问题使用固定安全中文错误，不保存操作系统原始异常或绝对敏感路径。

## 下载完成链路

`MediaDownloader` 在写入媒体时维护 SHA-256：

- 全新下载直接累计每个网络块。
- 断点续传通过 `asyncio.to_thread` 分块读取既有 `.part` 计算前缀哈希，再继续累计网络块。
- 已存在且大小正确的最终文件通过 `asyncio.to_thread` 分块计算哈希后登记完成。
- 最终大小校验通过并原子改名后，用仓库的完成接口一次写入字节数、完成状态、SHA-256、`verified` 和校验时间。

网络块的增量哈希只做内存计算；任何需要重新读取完整文件或分片的工作都通过 `asyncio.to_thread` 执行，不把大文件读盘放到 GUI 事件循环。暂停或取消时只保留 `.part` 和下载进度，不写入完成哈希。

## 完整性服务

新增独立 `FileIntegrityService`，只依赖 `PortablePaths` 与仓库协议：

1. 接收去重后的媒体 ID 列表，只处理状态为完成或完整性异常的记录。
2. 对每个目标先执行应用目录边界检查，再检查存在性和已知大小。
3. 分块计算 SHA-256；若没有旧基线则建立基线，有基线则比较。
4. 每完成一个媒体回报“当前项/总数、文件名、结果”，并在文件块之间检查取消标记。
5. 每个结果立即原子落库；取消只停止尚未开始或尚未完成的项，不回滚已经确认的结果。

服务返回结构化汇总：已校验、已建立基线、缺失、大小异常、哈希异常、跳过和取消数量。控制器只把这些安全计数展示给用户。

## 精准修复

“重新下载所选”仅接受 `missing`、`size_mismatch` 或 `hash_mismatch` 媒体：

- 路径越界立即拒绝。
- 最终文件存在时移动为 `<原文件>.corrupt`；若重名则使用 `.corrupt.2`、`.corrupt.3`。
- 同名 `.part` 存在时同样移动到冲突安全的 `.part.corrupt*`，避免混用不可信分片。
- 仓库把指定媒体重置为 `queued`、字节数 0、重试数 0、完整性 `unverified`，并清空下载错误和哈希基线。
- 调度器新增指定媒体执行入口，只下载传入 ID，不顺带重试同任务下其他网络失败项；执行后根据任务全部媒体状态重新计算任务状态。

修复过程中再次失败时沿用现有安全重试、FloodWait、断网恢复和磁盘空间处理。留档文件不进入任务去重，也不由普通卸载自动删除。

## 界面与交互

任务详情表允许多选，并新增“完整性”列：未校验、已校验、文件缺失、大小异常、哈希异常。校验时间通过工具提示展示，避免进一步挤压窄窗口。

详情标题区提供：

- `打开文件`：仅单选一个已完成且未标记完整性异常的媒体时启用；点击后仍重新检查实际文件和路径边界。
- `校验所选`：至少选择一个可校验媒体时启用。
- `重新下载所选`：至少选择一个完整性异常媒体时启用，并弹出说明留档行为的确认框。

任务操作区增加 `校验文件`，可对一个或多个已完成/部分失败任务中的可校验媒体执行批量校验。校验期间显示专用进度条、当前文件和取消按钮；相关校验/修复按钮禁用，下载暂停、界面导航和窗口关闭仍可工作。结束后刷新任务摘要和当前单任务明细，并显示结构化计数。

在 1180×720 最小验收窗口下，详情按钮允许紧凑排列；不新增常驻侧栏或独立导航页。

## 错误与安全边界

- 所有目标、`.part` 和 `.corrupt*` 路径必须通过 `PortablePaths.guard`。
- 文件消失、权限变化或读盘失败只影响当前媒体，批量校验继续处理其他项。
- 日志和界面不显示 Telegram 原始实体、API 凭据、会话或完整绝对文件路径。
- SHA-256 属于文件内容指纹，只保存在本地任务数据库，不上传到 GitHub、魔搭或 Telegram。
- 发布 ZIP 不包含数据库、哈希、校验报告、损坏留档或下载文件。

## 测试与验收

自动化测试覆盖：

- 旧 schema 幂等迁移、完整性字段校验与旧记录保留。
- 全新下载、断点续传、已有正确文件的 SHA-256 登记；暂停和失败不误写完成基线。
- 未校验基线、正常复查、缺失、大小异常、同尺寸内容异常、路径越界、读盘失败和取消。
- 指定媒体修复只重下所选项，损坏最终文件与 `.part` 冲突安全留档，其他失败项不被顺带重试。
- 控制器进度、取消、重复动作抑制、状态刷新和安全提示。
- 任务详情多选、按钮启用规则、完整性列与 1180×720/1280×780 布局。
- 使用真实数据的隔离副本建立旧文件基线，修改同尺寸字节后检出，再用受控假网关修复；原始直启数据不被测试修改。
- 三轮完整测试与 Ruff、便携包自检、安装器冒烟、ZIP 隐私扫描、v0.8.0 到 v0.9.0 签名更新与数据保留。

正式发布仍使用 GitHub / 魔搭双源事务：同一标签与提交、Ed25519 清单、SHA-256 资产校验、上传后回下载逐字节比较，最后推进 stable 指针。

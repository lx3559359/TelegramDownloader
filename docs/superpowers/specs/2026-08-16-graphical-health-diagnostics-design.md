# TelegramDownloader v0.10.0 图形化健康诊断设计

日期：2026-08-16

状态：已按用户的持续目标模式及“后续按建议执行、不再询问”授权定稿

## 背景与目标

v0.9.0 已具备登录恢复、连接重试、群组同步、内容搜索、自动订阅、可恢复下载、文件完整性修复和双源签名更新，但运行状态分散在不同页面。现有 `--self-test` 只能从命令行检查依赖和路径，无法直接回答真实使用中的“会话是否有效、数据库是否健康、磁盘是否够用、Telegram 是否授权、GitHub/魔搭更新源是否正常”。遇到问题时，用户只能提供截图，缺少可重复、可安全分享的结构化证据。

v0.10.0 新增图形化“健康诊断”中心和项目内脱敏诊断包。成功标准是：

- 在主界面中一键执行本地路径、磁盘、运行组件、任务库、内容库、登录会话、Telegram 连接和双源更新检查。
- 每项检查显示等待、执行中、正常、警告、失败、已跳过或已取消状态，显示安全说明和耗时。
- 检查有总进度、当前步骤和取消按钮，不阻塞 Qt 事件循环，不与已有连接恢复或更新下载发生竞态。
- 诊断结果只包含结构化状态和计数，不包含账号、群组、消息、搜索词、文件名、完整绝对路径、日志正文或凭据。
- 可把当前报告导出为 ZIP，固定保存到 `<应用目录>/data/diagnostics`；不使用系统临时目录或 C 盘业务目录。
- `--self-test` 与图形化本地检查共享核心探针，避免两套健康判断逐渐不一致。
- v0.9.0 的设置、DPAPI 会话、数据库、任务、搜索、订阅、下载和完整性记录无损保留。

## 方案比较

### 方案 A：图形化健康诊断与脱敏报告（采用）

把现有命令行自检扩展为用户可见、可取消的诊断流水线，并补齐 Telegram、数据库、磁盘和更新源状态。它直接降低此前连接、同步、搜索、下载和更新问题的定位成本；所有检查均为只读或使用项目内临时写入探针，风险低。

### 方案 B：跨任务本地下载库

增加全局文件搜索、筛选、打开和批量校验。它能改善大量下载后的查找体验，但任务中心已经提供任务搜索、媒体明细、打开、校验和修复，当前增益低于诊断闭环。

### 方案 C：存储清理中心

统计并删除 `.corrupt*`、残留 `.part`、缓存和旧更新备份。它能释放空间，但涉及不可逆删除、活动下载判断和任务记录一致性，不适合与首个诊断中心同时交付。本版只报告空间与分类计数，不执行清理。

## 架构与边界

新增 `diagnostics.py`，保持四个清晰边界：

1. `DiagnosticProbe`：一个有稳定 ID、中文标题和异步执行方法的检查单元。
2. `DiagnosticsService`：按计划调度本地与网络探针、汇总进度、处理取消并生成不可变报告。
3. `DiagnosticReportStore`：在项目内原子保存最新 JSON，并按用户操作导出 ZIP。
4. `DiagnosticsPage`：只负责展示、发出运行/取消/导出/打开目录信号，不直接访问文件、SQLite 或网络。

控制器装配当前仓库、目录仓库、网关和更新协调器所暴露的窄协议。诊断服务不调用下载规划器、调度器或更新下载器，不创建任务、不推进搜索或订阅游标、不下载更新包。

`UpdateCoordinator` 新增公开的只读来源检查方法，返回现有 `SourceCheck` 结构；`check_for_update()` 复用该方法。这样诊断中心不依赖私有方法，也不会改变现有双源一致性与签名策略。

## 报告模型

状态固定为：

- `pending`：尚未开始。
- `running`：正在执行。
- `passed`：检查正常。
- `warning`：功能可继续使用，但需要用户关注。
- `failed`：该能力当前不可安全使用。
- `skipped`：前置条件不存在，例如尚未配置账号时跳过在线授权检查。
- `cancelled`：用户取消时尚未完成的检查。

每项结果只保存：`id`、`title`、`status`、`code`、`summary`、`durationMs` 和白名单结构化 `metrics`。`code` 为稳定英文标识，`summary` 为固定中文文案；禁止保存原始异常文本。完整报告保存：

- `schemaVersion=1`、应用版本、UTC 开始/结束时间和总状态。
- 冻结运行标志、Windows x64 标志、应用路径是否为非系统盘、可写路径是否全部受项目根保护。
- 磁盘总量和可用量，不保存盘符或应用绝对路径。
- 两个数据库的 `PRAGMA quick_check` 结果、schema 版本及任务/媒体/搜索/订阅等总数，不保存任何行内容。
- 设置可读、凭据文件存在和 DPAPI 解密成功三个布尔状态，不保存 API ID、API Hash、手机号、代理或会话值。
- Telegram 未配置、未登录、已授权、暂时不可达或会话失效状态及耗时，不保存账号资料。
- GitHub 与魔搭各自的有效、不可用或无效状态、发现版本和耗时；签名不一致必须失败。

总状态规则：任一安全关键本地检查或任一更新源“无效签名”时为失败；只有空间偏低、未登录或单个网络来源不可用时为警告；全部适用检查通过时为正常；取消时为已取消。

## 检查流程

一次运行使用固定顺序，便于进度可解释：

1. **运行环境与路径**：验证版本、Windows x64、运行根、13 个可写位置和新增诊断目录均经过 `PortablePaths.guard`；冻结正式版若位于系统盘则失败，源码开发运行只警告。
2. **项目内写入**：在 `data/temp/diagnostics` 创建随机小文件、`flush/fsync` 后读取比对并删除；无论成功失败都尽力清理，只报告固定结果。
3. **磁盘空间**：使用运行根所在卷；可用量低于 1 GiB 为警告，低于 256 MiB 为失败，其余通过。
4. **运行组件**：检查 PySide6、Telethon、qasync、qrcode、sqlite3 和 Windows DPAPI，与 `--self-test` 使用同一纯函数。
5. **任务数据库**：通过只读 SQLite 连接执行 `PRAGMA quick_check`，检查必需表和完整性字段，输出 schema 与状态计数。
6. **内容数据库**：只读执行 `PRAGMA quick_check`，检查账号、会话、搜索、订阅表，输出 schema 与计数。
7. **本地凭据状态**：检查设置读取结果、凭据文件存在及启动时 DPAPI 解密结果，只报告布尔值。
8. **Telegram 授权**：没有已加载网关时跳过并提示先登录；有网关时复用现有连接恢复互斥，随后调用 `test_connection()` 验证授权。会话失效为失败，瞬时网络/代理错误为警告。
9. **签名更新源**：并发检查 GitHub 和魔搭 latest、清单与 Ed25519 签名；双源同版本内容不一致或任一来源返回无效签名为失败，单源暂时不可达为警告。

本地文件和 SQLite 检查通过 `asyncio.to_thread` 执行；网络探针使用现有异步客户端。每步结束立即发出进度。重复点击复用同一个运行任务；取消设置事件并取消尚未完成的网络调用，已经完成的结果不回滚。

## 图形界面与交互

左侧导航新增“健康诊断”，页面采用不增加弹窗层级的两区布局：

- 顶部显示总状态、上次完成时间、当前步骤和 0–100% 进度条。
- 中部表格显示检查项、状态、耗时和安全说明；状态使用文字与颜色共同表达，不能只依赖颜色。
- 底部提供“开始自检”“取消”“导出诊断包”“打开诊断目录”。运行期间开始和导出禁用，取消启用；完成后导出启用。

进入页面不会自动触发网络请求。若 `data/diagnostics/latest.json` 存在且格式有效，先显示上次结果并明确标注“历史结果”；用户点击开始后再刷新。关闭窗口时沿用现有异步动作收敛，诊断任务必须可取消并在应用退出前结束。

诊断页面在 1180×720 和 1280×780 下完整显示；表格可纵向滚动，按钮不挤出窗口。打开诊断目录必须先通过路径边界检查。

## 诊断包与隐私

`PortablePaths` 新增 `diagnostics`，固定为 `<应用目录>/data/diagnostics`。运行结束时原子更新 `latest.json`；用户点击导出后生成 `TelegramDownloader-diagnostics-<UTC>.zip`，ZIP 仅包含：

- `diagnostic-report.json`：规范 JSON 报告。
- `diagnostic-summary.txt`：由报告白名单字段生成的简体中文摘要。

明确不包含：`secrets.dat`、`settings.json` 原文、SQLite 数据库、应用日志、搜索历史、缩略图、下载文件、`.part`、`.corrupt*`、更新包、账号/群组/消息/文件标识、绝对路径、环境变量或系统用户名。ZIP 生成到同目录临时文件，`fsync` 后原子替换；重名使用 UTC 时间和安全序号，不覆盖旧报告。

报告保存和导出前执行递归隐私验证：键名白名单、字符串禁止匹配已登记秘密、手机号、二维码登录 URL、Telegram 链接、Windows 绝对路径或运行根文本。验证失败时不留下 ZIP，并只显示固定安全错误。

## 错误处理

- 单个非关键探针失败不终止后续探针；路径逃逸、写入失败、数据库损坏和无效更新签名标为失败。
- 原始 `OSError`、SQLite 错误、Telegram 异常和 HTTP 响应正文只转换为稳定错误码，不进入报告或界面。
- 没有账号不是程序故障，Telegram 探针标为跳过并给出操作建议。
- 单个更新源不可达不阻断应用，标为警告；来源返回可读取但无效的签名或同版本不一致内容标为失败。
- 取消不会删除已经存在的旧报告或导出包；本次未完成结果只保存在内存，除非能够生成通过隐私验证的 `cancelled` 报告。
- 诊断运行不得暂停下载、修改任务状态、推进订阅游标或弹出登录二维码。

## 兼容性与数据边界

- 不修改任务库或内容库 schema，不触碰现有行。
- v0.9.0 用户数据原位使用；新增目录只位于应用根下。
- 正式便携 ZIP 和安装器继续排除 `data/`、`downloads/` 和所有诊断报告。
- 在线更新继续保留整个 `data` 与 `downloads`，因此用户导出的诊断包升级后仍在项目内。
- 不新增 Windows 服务、计划任务、注册表业务设置、系统凭据或 C 盘持久业务文件。

## 测试与验收

自动化测试覆盖：

- 状态模型、总状态归并、固定错误码、耗时边界和取消语义。
- 路径全部受根保护、项目内写入探针成功/失败/清理、磁盘阈值。
- 两个真实临时 SQLite 数据库的 `quick_check`、schema/必需列/计数；损坏库和锁冲突只输出安全错误。

## 明确不做

- 不删除或自动清理下载、`.part`、`.corrupt*`、日志、缓存或更新备份。
- 不导出原始日志、设置、数据库、会话或用户内容。
- 不后台自动运行完整网络诊断，不增加遥测或上传诊断报告。
- 不绕过 Telegram 权限、内容保护、FloodWait 或会话授权。
- 不在本版同时增加下载库、批量链接导入、带宽限速、时段调度或系统通知。

# 健康诊断与命令级自检加固设计

## 目标

本次改动修复健康诊断和 `--self-test` 已确认的误报与副作用，使“正常”结果能够代表当前真实运行状态，同时保持诊断输出严格脱敏。

成功标准：

- `--self-test` 不再修改任务、媒体、搜索或订阅的业务状态，并且主程序运行时不能并发执行命令级自检。
- 运行中的 WAL 数据能够被数据库探针看到，全部检查在同一个只读快照中完成。
- 外键损坏、未知业务枚举值和不兼容结构都必须返回异常，不能只记录 `Other` 指标后继续显示正常。
- 仅有可解密但内容为空的凭据文件不能显示“凭据可用”。
- 自定义下载根目录的安全边界、可写性和磁盘空间都进入诊断范围。
- Telegram 与更新源检查有明确总时限；取消后不遗留由诊断启动的共享重连任务。
- 界面提供固定处理建议和脱敏指标，不展示账号、群组、消息、文件名、路径、搜索词或密钥。

## 非目标

- 不自动修复数据库、凭据、网络、路径或更新源。
- 不修改已有数据库业务表结构，不增加业务数据迁移。
- 不创建数据库副本或收集原始日志。
- 不改变下载调度、账号登录、自动订阅或在线更新的正常业务流程。
- 本设计不包含版本号提升、发布或稳定更新指针推进。

## 方案选择

采用现有架构内的定点加固：保留 `DiagnosticsService`、探针、报告存储和现有维护中心页面，只收紧探针契约并补充安全展示。

未采用以下方案：

- 数据库快照诊断：能完全隔离检查，但大数据库会增加磁盘占用、复制时间和清理复杂度。
- 独立 Doctor 子进程：隔离最强，但会扩大进程通信、打包、自检和更新回滚的维护面。

当前方案能够直接修复已复现问题，并保持诊断包格式和主界面结构稳定。

## 命令级自检边界

`run_self_test()` 继续承担冻结运行时导入、受管路径、数据库初始化兼容性和报告写入检查。它允许创建缺失目录、初始化或迁移数据库结构并写入 `data/logs/self-test.json`，但不得调用任何业务状态恢复方法。

具体约束：

- 移除 `TaskRepository.recover_interrupted()`。
- 移除 `CatalogRepository.recover_interrupted_subscriptions()`。
- 对已有任务、媒体、搜索、订阅记录及其更新时间做前后不变回归测试。
- 正常 GUI 启动继续执行现有中断恢复，升级后恢复语义不变。
- `--self-test` 与 `--update-health-check` 进入数据库前先取得现有单实例互斥锁；如果主程序正在运行，命令返回非零且不打开提示对话框、不访问业务数据库。
- 更新助手原本就在父进程退出后执行 `--update-health-check`，因此能够正常取得互斥锁；若有新实例竞态启动，健康检查失败并交由现有更新事务回滚。

命令级自检不是纯文件系统只读操作，但必须是“业务数据只读”。这一边界会写入 README 和测试契约，避免把结构初始化与业务恢复混为一谈。

## WAL 一致性与数据库语义检查

### 只读快照

数据库连接由 `mode=ro&immutable=1` 改为 `mode=ro`，继续启用 `query_only=ON`。打开连接后显式开始只读事务，使 `quick_check`、结构检查、语义检查和聚合计数共享同一 WAL-aware 快照。

连接不得执行 checkpoint、写事务或修复。数据库不存在、无法读取、被占用超时或快照建立失败时，仍映射为现有固定安全错误码。

### 结构与关系

任务库和内容库都执行：

1. `PRAGMA quick_check`；
2. 必需表与列检查；
3. `PRAGMA foreign_key_check`，只判断是否存在结果，不导出表名、行号或原始数据；
4. 业务枚举域检查。

任务库至少校验：

- `tasks.source_kind`、`tasks.status`、可空的 `tasks.pause_reason`；
- `media_items.media_kind`、`media_items.status`、`media_items.integrity_status`。

内容库至少校验：

- `dialogs.kind`；
- `search_sessions.status` 和 `search_sessions.scope`；
- `search_results.media_kind`；
- `subscription_rules.state`；
- `subscription_runs.status`。

未知值、悬空外键或语义查询失败统一返回固定的数据库语义异常结果。报告只增加 `foreignKeysValid` 和 `stateValuesValid` 等布尔指标；不会导出非法值、表名、记录标识或路径。现有聚合计数继续保留，但任何 `Other` 计数都不能与“正常”状态并存。

## 凭据诊断

凭据探针区分四个概念：

- 设置文件可读取；
- 凭据文件存在；
- 凭据文件可解密；
- Telegram API 凭据已完整配置。

“已完整配置”的条件是设置中的 `api_id > 0` 且解密结果中的 `api_hash` 去除空白后非空。`session` 和代理密码不是完成基础配置的必要条件。

状态顺序：

1. 设置不可读：异常；
2. 凭据文件不存在：需关注，尚未配置；
3. 凭据文件不可解密：异常；
4. 文件可解密但 API ID/Hash 不完整：需关注，尚未配置；
5. 基础 API 凭据完整：正常。

新增指标只能是 `credentialsConfigured` 布尔值，不导出 API ID、Hash、Session 或代理内容。

## 下载根目录与磁盘检查

环境探针继续验证所有受管路径的安全边界。项目写入探针扩展为两个独立动作：

- 在应用诊断临时目录写入、同步、读回并删除随机标记；
- 使用现有 `DownloadPathPolicy` 对当前下载根目录执行零内容临时文件写入、同步和删除。

第二项失败时返回固定的下载目录不可写结果，不回退到默认目录，也不在报告中记录实际路径。

磁盘探针检查应用根目录所在卷和当前下载根目录所在卷：

- 同卷时只调用一次磁盘查询，并标记 `downloadSameVolume=true`。
- 不同卷时分别记录应用卷与下载卷的总空间、可用空间。
- 任一卷低于 256 MiB 为异常；低于 1 GiB 为需关注。
- 结果说明区分“应用所在磁盘”和“下载所在磁盘”，但不输出盘符或路径。

保留现有应用卷 `totalBytes`、`freeBytes` 指标以兼容诊断报告；新增下载卷指标必须进入诊断存储白名单和隐私测试。

## 网络时限与取消

Telegram 健康检查不再调用共享 `ConnectionRecovery.ensure_connected()`。诊断直接对当前网关执行一次可取消的 `test_connection()`，并由探针施加固定总时限。超时映射为网络暂不可用的需关注状态，不写入异常文本。

更新源检查保留双源并发和 HTTP 客户端自身的 15 秒时限，在探针外再设置略大的总时限，防止第三方实现或未来改动无限等待。

固定默认时限：

- Telegram：20 秒；
- 双更新源：20 秒。

时限通过可注入参数测试，不依赖真实等待。

线程化本地探针无法安全终止底层线程，仍采用“当前项收敛后停止”。用户点击取消后：

- 页面立即显示“正在取消，当前本地检查完成后停止”；
- 禁用重复取消；
- 已完成结果保留；
- 未开始结果标记已取消；
- 网络探针任务立即取消，且不留下由诊断启动的共享重连任务。

## 界面与脱敏展示

诊断结果表保留检查项、状态、耗时和说明。页面增加一个随选中行更新的详情区域，包含：

- 固定处理建议；
- 已通过诊断存储契约允许的安全指标。

处理建议由 `result.code` 映射到固定中文文本。例如：

- 磁盘不足：清理对应存储后重新检查；
- 下载目录不可写：在设置中重新选择可用目录；
- 数据库损坏或语义异常：停止程序、备份数据目录后再处理；
- 凭据未配置或不可解密：重新录入 Telegram API 凭据；
- 会话失效：重新登录；
- 更新源异常：检查网络，持续失败时使用正式发布页覆盖安装。

指标名称和值使用固定翻译，不直接调用任意对象的字符串表示。未知指标不显示。布尔、字节数、毫秒、状态枚举、版本号和固定授权原因使用各自格式化器。

诊断包继续只包含 `diagnostic-report.json` 与 `diagnostic-summary.txt`。新增错误码、指标和固定说明必须同时更新序列化白名单、反序列化契约、隐私扫描与 E2E 导出测试。

## 错误处理

- 探针内部异常继续映射为固定错误码，不显示异常消息或绝对路径。
- WAL 只读连接或事务失败不得回退到 `immutable=1`，避免静默读取过期数据。
- 语义检查不能确定结果时按异常处理，不能按正常处理。
- 下载根目录离线或不可写时只报告，不修改用户设置、不创建默认回退任务。
- 命令级自检遇到已有实例时不触发激活窗口，直接返回可供脚本判断的固定非零状态。
- UI 详情格式化失败时隐藏该指标并保留固定处理建议，不影响完整报告保存。

## 测试设计

所有生产代码改动遵循红—绿—重构循环，每个行为先观察对应测试因缺少实现而失败。

必需回归测试：

1. WAL 中未 checkpoint 的最新任务和内容记录可被探针看到。
2. `foreign_key_check` 有结果时数据库探针失败。
3. 每个受检枚举列出现未知值时数据库探针失败，报告不包含未知原值。
4. 空但可解密的凭据文件与 `api_id=0` 返回未配置；完整 API ID/Hash 才通过。
5. 自定义下载根目录不可写、离线、空间不足和不同卷时分别得到正确结果，报告不包含路径。
6. Telegram 与更新源超时无需真实等待，且取消后没有存活的诊断网络任务。
7. 线程化本地探针取消时页面进入“正在取消”，收敛后剩余项标记取消。
8. `run_self_test()` 前后下载中任务、媒体状态、订阅状态和更新时间完全不变。
9. 主程序实例存在时 `--self-test` 与 `--update-health-check` 在访问数据库前退出。
10. 新增详情区域只显示固定建议和白名单指标，隐私值、路径和未知指标不显示。
11. 历史报告、实时报告和导出包的新旧允许结果都能稳定往返。

最终验证包括：

- 诊断、控制器、UI、命令级自检和打包契约专项测试；
- 完整 pytest；
- Ruff；
- 源码 `run_self_test()` 隔离目录检查；
- 冻结程序 `--self-test`；
- 便携包构建及安装器冒烟测试；
- 工作树和产物隐私扫描。

## 兼容性

- 诊断报告 schema 继续为 1；只增加白名单内的固定错误码和指标。
- 历史报告继续可读，旧报告没有新增指标时详情区域只显示已有信息。
- 不改变设置文件、密钥文件或业务数据库格式。
- 更新助手继续以退出码和确认文件判断健康状态。
- 正常启动的中断恢复语义保持不变，只从命令级自检中移除重复调用。

# 账号安全重登、手动更新、搜索单行与“TG 快取”品牌设计

日期：2026-08-23  
基线版本：v0.16.0  
状态：设计已由用户逐段确认，等待书面规格复核

## 1. 目标

本次改造解决四个用户可见问题：

1. 已登录用户误点“账号登录”时，程序不得创建二维码、断开连接或改变当前会话。用户应先看到当前账号与连接状态，只有明确选择“重新登录 / 切换账号”并确认后，才进入认证流程。
2. 搜索结果摘要取消自动换行，恢复固定行高和单行省略号；完整摘要继续通过悬停提示提供。
3. 在设置中提供清晰、独立、可发现的“关于与更新”入口。更新检查完全由用户手动触发，检查、确认、下载和安装均有明确状态。
4. 用户可见品牌改为“TG 快取”，副标题为“媒体下载器”，采用“取件盒 / 文件夹 + 向下箭头”的新 Logo 与应用图标。

## 2. 已确认的产品原则

- 查看账号状态是只读操作，零认证副作用。
- 重新登录采用候选会话；候选失败或取消不得影响当前账号。
- 候选账号成功后才允许替换当前账号，切换过程支持回滚。
- 不在应用启动时自动检查或安装更新。
- 搜索结果优先保持列表密度和滚动稳定性。
- 用户可见品牌全面更新，内部兼容标识在本次过渡版本保持稳定，确保 v0.16.0 可原地升级。
- 本次交付必须完成三轮独立自检。

## 3. 范围

### 3.1 包含

- 主导航“账号登录”的安全分流。
- 新的账号状态窗口与重新登录二次确认。
- 候选 Telegram 网关、候选认证状态和原子账号切换。
- 不同账号切换前的再次确认，以及活动下载保护。
- 设置中的独立“关于与更新”标签页。
- 手动更新检查状态、最近成功检查时间和安装确认。
- 搜索结果摘要单行省略、固定行高与全文工具提示。
- 名称、Logo、窗口图标、托盘图标、通知、快捷方式和安装器品牌更新。
- 旧版安装、数据目录、更新清单和自动启动路径兼容。
- 自动化测试、完整工程检查和 Windows 实机验收。

### 3.2 不包含

- 多账号同时在线或账号列表管理。
- 自动更新、静默安装或定时检查更新。
- 搜索结果详情侧栏、摘要编辑或新的内容预览功能。
- Python 包名、Git 仓库名、数据目录结构的迁移。
- 在本次过渡版本中修改主程序内部可执行文件名。
- 对下载、搜索、订阅以外模块的无关重构。

## 4. 当前问题与根因

### 4.1 账号登录误触

`AppController.show_login()` 当前只要检测到网关、API ID 和 API Hash，就直接调度 `begin_qr_login()`。该判断只能证明本地存在 API 配置，不能证明用户需要重新认证，也没有检查当前账号是否已经授权。因此主导航点击会无条件创建新的二维码会话。

### 4.2 手动更新入口不可发现

更新按钮当前嵌在“设置 → 常规”的普通表单行内。虽然信号和更新协调器已经接线，但入口不具备独立信息层级，用户无法稳定找到，也无法从设置标签名称判断更新功能所在位置。

### 4.3 搜索摘要换行过重

当前搜索表格启用了 `WrappedSummaryDelegate`、自动换行、动态行高、可见行重测定时器和尺寸缓存。该实现能展示全文，但牺牲了列表密度，并增加了滚动和列宽变化时的布局工作。

### 4.4 品牌资源缺失

当前主界面仅使用文字 “T” 作为标记，PyInstaller 和安装器没有完整接入正式品牌图标。窗口标题、通知、登录窗口和安装器等位置仍散落使用“Telegram 下载器”文本。

## 5. 用户体验设计

### 5.1 账号状态入口

当用户主动点击主导航“账号登录”时：

- 当前账号已授权：打开“账号状态”窗口。
- 当前会话存在但连接异常：打开“账号状态”窗口，显示连接异常和“重新连接”；不得自动进入二维码。
- 已明确判定会话失效：打开状态窗口，显示“登录已失效”，提供明确的“重新登录”按钮；不得因为导航点击本身创建二维码。
- 没有 API 凭据或从未登录：进入现有首次登录流程。

应用首次启动且没有可用会话、后台事件明确报告授权失效等既有必需登录场景可以继续主动展示登录引导。本次限制针对用户主动点击导航时的误触副作用，不取消必要的授权恢复提示。

账号状态窗口展示：

- 当前 Telegram 账号显示名。
- 授权状态和连接状态。
- 本地会话是否已加密保存。
- 搜索和订阅是否可用。
- “重新连接”“重新登录 / 切换账号”“关闭”操作；仅在相应状态下显示可用操作。

### 5.2 重新登录与切换账号

用户点击“重新登录 / 切换账号”后先显示二次确认，说明：

- 当前账号不会立即退出。
- 候选登录取消或失败时继续使用当前账号。
- 活动下载必须先暂停或完成。
- 如果登录的是不同账号，程序将在识别出候选账号后再次确认。

存在活动下载时，不启动候选认证。窗口明确提示用户先暂停或等待活动下载完成；程序不自动暂停任务。排队、暂停、完成和历史任务均保留。

候选账号登录成功后：

- 若账号 ID 与当前账号相同，按重新授权处理，不再要求账号切换确认。
- 若账号 ID 不同，展示当前账号与候选账号显示名，要求最终确认。
- 用户取消不同账号确认时，销毁候选网关并保留当前账号。

### 5.3 设置中的关于与更新

设置新增第四个一级标签“关于与更新”，不再把更新入口嵌在“常规”表单行。

标签页展示：

- 品牌名称“TG 快取”和副标题“媒体下载器”。
- 当前版本与发布通道。
- “检查更新”主按钮。
- 最近一次成功检查时间；从未成功检查时显示“尚未检查”。
- 当前操作状态和最终结果。

状态文案必须区分：

- 正在检查。
- 当前已是最新正式版。
- 发现新版本，等待用户查看和确认。
- 用户取消更新。
- 网络或更新源暂不可用，可重试。
- 更新清单或签名校验失败，已阻止更新。
- 更新下载或安装启动失败，当前版本未改变。

检查更新不会自动保存设置对话框中的其他未保存字段。最近成功检查时间由更新控制器单独、即时写入非敏感设置。

### 5.4 搜索结果摘要

- 搜索结果表格固定为缩略图所需的统一行高。
- 摘要列使用单行显示和右侧省略号。
- 摘要列继续占用表格剩余宽度。
- 表格继续禁止水平滚动条。
- 摘要列 `ToolTipRole` 继续返回完整文本。
- 短摘要在可用宽度内完整显示。
- 表格滚动时不再重测摘要高度。

### 5.5 品牌方向

用户确认的品牌为：

- 主名称：`TG 快取`
- 副标题：`媒体下载器`
- 图形：圆角方形底，青色到蓝色渐变；内部为简化取件盒或文件夹轮廓与向下箭头。
- 小尺寸原则：16–32 像素只保留轮廓和箭头，不在图标内放置中文或 “TG” 字样。

用户可见品牌覆盖：

- 主窗口标题、侧栏品牌、启动提示。
- 登录、账号状态、设置和更新窗口标题。
- 托盘图标、托盘提示、系统通知来源名称。
- 任务栏和窗口图标。
- 开始菜单与桌面快捷方式名称和图标。
- 安装器显示名称、安装器图标、卸载显示名称与图标。
- README 和后续发行说明中的产品名称。

## 6. 架构与组件

### 6.1 `AccountStatusDialog`

新增独立账号状态窗口，而不是把只读状态塞入认证用 `LoginDialog`。该窗口只负责呈现 `AccountStatusSnapshot` 并发出以下意图信号：

- `reconnect_requested`
- `reauthenticate_requested`
- `close_requested`

它不持有 Telegram 网关，不创建异步任务，也不直接修改会话。

`AccountStatusSnapshot` 至少包含：

- `display_name`
- `account_id`（只供逻辑比较，不在界面展示）
- `authorization_state`
- `connection_state`
- `session_encrypted`
- `content_available`
- `subscriptions_available`
- `active_download_count`

### 6.2 主动登录入口分流

主导航信号改接控制器的新入口 `show_account_access()`。该入口基于控制器已有状态和非破坏性授权探测选择账号状态窗口或首次登录窗口。

该方法不得调用：

- `begin_qr_login()`
- `refresh_qr_login()`
- `gateway.disconnect()`
- 前台搜索、订阅探测或下载取消逻辑

只有账号状态窗口发出的明确重新登录意图才能创建候选认证。

### 6.3 `CandidateLoginSession`

新增候选登录会话边界，封装：

- 候选网关。
- 候选二维码等待任务。
- 候选手机号、验证码和两步验证状态。
- 候选账号 ID、显示名和导出的会话字符串。
- 取消、销毁和失败清理。

候选网关使用已保存的 API ID、API Hash 和代理配置创建，但初始 Telegram 会话为空。候选流程不得覆盖 `AppController.gateway`、当前加密会话或在线服务引用。

同一时间只允许一个候选登录会话。重复点击重新登录时聚焦现有认证窗口，不创建第二个候选网关。

### 6.4 在线服务分段构建

当前 `build_services()` 同时创建下载服务并绑定共享内容服务。为支持安全切换，将其拆分为两个边界：

1. `build_online_services(gateway, settings)`：创建候选账号所需的 planner、downloader 和 scheduler，不修改控制器或共享页面状态。
2. `bind_online_services(bundle)`：在提交阶段把内容浏览、订阅和控制器引用绑定到已验证的服务包。

服务包使用具名数据结构保存 gateway、planner 和 scheduler，避免通过不透明元组判断长度。

### 6.5 原子账号切换协调

候选认证成功并通过必要确认后，控制器按以下顺序提交：

1. 再次确认 scheduler 快照中的活动任务数为零，并阻止新的下载调度进入活动状态；排队、暂停和等待用户操作的任务不属于活动下载。
2. 等待或取消当前前台搜索、缩略图请求和订阅探测；不删除其持久化数据。
3. 构建候选在线服务包，尚不修改当前引用。
4. 保存当前服务包和当前加密会话作为回滚快照。
5. 在内存中绑定候选服务并更新账号内容上下文，完成可逆健康检查后原子保存候选会话；会话保存成功且控制器引用更新完成构成提交点。
6. 恢复调度准入与连接监控。
7. 成功后关闭旧 scheduler 并断开旧 gateway。

提交点之前任一步骤失败时：

- 恢复旧服务引用和共享服务绑定。
- 恢复旧加密会话；会话文件写入继续使用已有原子替换能力。
- 恢复旧账号显示和调度准入。
- 销毁候选服务与候选网关。
- 显示安全、非敏感的失败提示。

提交点之后关闭旧 scheduler 或旧 gateway 失败时，不回滚已经可用的新账号。控制器记录非敏感警告并继续执行幂等清理，确保旧连接最终释放。

### 6.6 手动更新边界

设置页只发出 `update_check_requested`。控制器负责：

- 去重当前更新检查任务。
- 驱动按钮忙碌状态。
- 调用现有受签名保护的更新协调器。
- 将结构化结果映射为界面状态。
- 仅在用户接受更新对话框后下载并启动安装器。
- 成功完成检查后立即保存 `last_successful_update_check_utc`。该字段是 `AppSettings` 中的 UTC ISO 8601 文本，空字符串表示从未成功检查；设置读取时验证格式并向后兼容缺失字段。

更新协调器不在 `AppController.start()` 或应用启动装配中注册自动检查任务。旧设置字段 `check_updates_on_startup` 继续被规范化为 `False`，不重新暴露开关。

### 6.7 搜索表格简化

移除搜索结果列对 `WrappedSummaryDelegate` 的依赖，以及以下动态布局链路：

- 可见结果行枚举仅用于摘要测量的部分。
- 摘要重测定时器。
- 摘要列尺寸变化后的缓存清理与重测。
- 模型重置、插入、删除和摘要变化触发的动态行高重测。
- 字体与屏幕变化触发的摘要尺寸缓存清理。

保留缩略图可见范围请求逻辑。表格改为 `setWordWrap(False)`、`ElideRight` 和统一默认行高。

### 6.8 品牌资源与常量

新增集中品牌模块，提供用户可见名称、副标题、通知来源名和资源路径。业务错误文案中需要描述 Telegram 服务时继续使用 “Telegram”，产品名称则统一来自品牌常量。

新增一份主矢量 Logo，并生成经人工检查的 ICO 和 PNG 尺寸集合。应用启动时设置全局窗口图标；PyInstaller 和 Inno Setup 显式引用 ICO。

为保障旧版本升级，本次保持以下内部标识：

- Python 包名 `telegram_downloader`
- Git 仓库与更新产品标识 `TelegramDownloader`
- 现有应用数据和下载目录结构
- 现有安装目录选择逻辑
- 过渡版本的内部主可执行文件名 `TelegramDownloader.exe`
- 更新辅助程序名和更新清单兼容字段

安装器保留现有 `AppId` `{B19D534A-A414-4D17-9BB6-CE9A60D8243C}` 识别旧安装，同时把用户可见 `AppName`、快捷方式和卸载显示名称更新为“TG 快取”。安装过程清理旧名称的开始菜单和桌面快捷方式，再创建新快捷方式；媒体、数据库、配置和加密会话不参与清理。

## 7. 数据流

### 7.1 查看账号

`主导航点击 → 控制器读取账号快照 → AccountStatusDialog`

该路径终止于只读窗口，不到达任何二维码 API。

### 7.2 候选重新登录

`账号状态窗口明确请求 → 活动下载检查 → 第一次确认 → 创建候选网关 → QR / 手机号认证 → 获取候选账号身份 → 必要时不同账号再次确认 → 原子服务切换 → 保存候选会话 → 销毁旧服务`

任一取消或失败分支都回到当前账号。

### 7.3 手动更新

`设置按钮 → 去重异步动作 → 获取并校验更新清单 → 映射检查结果 → 可选更新确认 → 可选下载与安装 → 更新状态与最近成功检查时间`

没有从应用启动到该流程的边。

### 7.4 搜索摘要

`SearchResult.excerpt → DisplayRole 单行省略显示`  
`SearchResult.excerpt → ToolTipRole 完整文本`

## 8. 错误处理与隐私

- 账号状态读取异常不得降级为自动二维码登录。
- 网络异常不得清空、覆盖或注销当前会话。
- 候选二维码 URL、API Hash、手机号、验证码、两步验证密码和会话字符串不得写入日志、测试快照或诊断报告。
- 候选登录错误继续通过安全错误映射展示，不直接暴露 Telegram 原始异常文本。
- 更新错误区分网络、源不可用、签名阻止、下载失败和安装启动失败；任何错误都恢复检查按钮。
- 更新签名失败必须阻止下载，不能提供绕过操作。
- 品牌迁移不得删除数据目录、下载目录、数据库、配置或凭据文件。
- 搜索工具提示只展示当前结果本来已经显示给用户的摘要，不引入新的数据持久化。

## 9. 测试与验收

### 9.1 第一轮：单元与集成测试

账号测试至少覆盖：

- 已授权时点击主导航不调用二维码、刷新二维码、断开连接或取消在线任务。
- 连接异常时只显示账号状态和重新连接。
- 无凭据时仍可进入首次登录。
- 候选登录取消、超时、网络失败和密码失败时旧会话保持不变。
- 候选登录重复触发只创建一个候选网关。
- 同账号重新授权不显示不同账号确认。
- 不同账号必须再次确认；取消后旧账号保持不变。
- 活动下载存在时不创建候选网关。
- 服务构建、绑定、凭据保存和旧服务关闭各阶段失败时可回滚。

更新测试至少覆盖：

- 设置存在独立“关于与更新”标签和可见检查按钮。
- 启动源码和运行测试均无自动更新调用。
- 重复检查去重，忙碌状态和按钮恢复完整。
- 最新版、新版本、取消、网络失败、源阻止和签名失败状态正确。
- 最近成功检查时间只在成功检查后更新，且不保存设置窗口其他未提交字段。
- 未经用户接受不下载或启动安装器。

搜索测试至少覆盖：

- 表格关闭换行并使用 `ElideRight`。
- 结果行高固定，不再安装摘要换行委托或运行重测定时器。
- 长摘要显示省略号语义，工具提示返回全文。
- 10,000 行结果滚动不触发动态摘要高度测量。

品牌测试至少覆盖：

- 所有用户可见窗口标题和主品牌区域使用集中常量。
- 应用、托盘、PyInstaller 和安装器均引用正式图标。
- 安装器稳定升级标识、数据目录保护和旧快捷方式迁移符合契约。

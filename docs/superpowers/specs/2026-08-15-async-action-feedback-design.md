# TelegramDownloader 异步操作可靠性与交互反馈设计

## 背景

v0.4.1 已在本地快进合并到 `main`。在使用真实程序恢复会话、进入账号内容页并进行界面审查时，运行时出现：

```text
TypeError: asyncSlot was not callable from Signal. Potential signature mismatch.
```

根因是当前 qasync 0.28.0 的 `asyncSlot` 包装器只有在收到至少一个信号参数时才会创建协程任务。应用把多个零参数 Qt 信号直接连接到 `@qasync.asyncSlot()`，因此账号内容页激活、手动刷新、手动重连以及部分登录操作可能在点击后没有执行。

本轮采用已确认的 A1 方案：在应用内增加集中式异步动作桥接，并统一必要的运行反馈。不会升级或维护 qasync 补丁，也不会重构下载、Telegram 或数据库架构。

## 目标

- 修复全部零参数异步信号无响应风险，而不是逐个按钮打补丁。
- 每个耗时操作都立即表明已经开始、当前状态和最终结果。
- 同一操作运行期间忽略重复触发，避免并发刷新、重连或登录切换。
- 成功、失败和取消后都恢复正确的按钮、进度和可重试状态。
- 保持账号缓存、搜索结果和历史在网络异常期间可浏览。
- 所有设置、凭据、数据库、日志、缓存、临时文件、下载和更新文件继续位于程序目录。

## 非目标

- 不改变现有左侧导航、深色主题或页面信息架构。
- 不修改 Telegram 数据模型、搜索目录结构、下载任务结构或更新协议。
- 不把所有带参数信号改造成新的事件总线。
- 不在日志、测试输出或界面错误中展示 API Hash、会话、手机号、验证码、密码或代理密码。

## 架构

### AsyncActionBridge

新增一个小型应用内桥接组件，职责仅限于把 Qt 零参数信号安全转换为 asyncio 任务。它提供以下能力：

- 通过稳定的动作键注册协程工厂，例如 `content.activate`、`dialogs.refresh` 和 `login.qr.refresh`。
- 信号触发时创建并保留任务引用，避免任务被回收。
- 同一动作键已有未完成任务时拒绝重复启动。
- 在动作开始、成功、失败、取消和结束时调用界面状态回调。
- 消费任务异常并交给现有安全错误处理；不让异常进入 Qt 的未处理回调。
- 关闭应用时取消并等待仍在运行的桥接任务。

桥接只负责调度和生命周期，不承载 Telegram、搜索或下载业务逻辑。业务仍由 `AppController` 完成。

### 接入范围

以下零参数异步连接统一接入桥接：

- 账号内容页激活。
- 群组与频道手动刷新。
- Telegram 手动重连。
- 二维码手动刷新。
- 切换到手机号登录。
- 修改 API/代理凭据。
- 取消登录。

带参数信号继续使用现有 qasync `asyncSlot`，包括链接扫描、手机号提交、验证码提交、密码提交、搜索、加载更多、预览和加入下载队列。

## 操作状态与反馈

### 通用规则

每个耗时动作遵循同一状态机：

1. 空闲：按钮可用。
2. 启动：立即显示运行中状态，并禁用同一动作的重复触发。
3. 运行：保留与当前动作无冲突的浏览、预览和历史操作。
4. 成功：显示明确结果或数量摘要。
5. 失败：显示安全中文错误和可重试入口。
6. 取消或结束：清除忙碌态并恢复按钮。

界面锁定以动作范围为单位，不锁定整个窗口。例如群组刷新时仍可浏览缓存群组和搜索历史。

### 群组刷新与重连

- 点击后按钮立即显示“刷新中…”或“重连中…”。
- 运行期间禁用同一按钮，但保留缓存内容可用。
- 刷新进度继续显示实时发现数量；完成后显示群组总数。
- 重连失败后恢复按钮，并保留“重新连接”入口。

### 搜索与加入队列

- 搜索继续显示已扫描数量、匹配数量、处理阶段和取消入口。
- 已返回结果在搜索继续或取消时保持可预览、可选择。
- 点击“加入下载队列”后立即显示“正在准备已选 N 项”，并禁止重复提交。
- 取消确认时显示“已取消创建任务”；成功后显示选择、加入、重复和不可用数量。

### 登录操作

- 二维码刷新、手机号切换、修改凭据和取消登录在执行期间显示处理中状态。
- 切换登录方式前先取消已有二维码等待任务，且不能叠加多个切换动作。
- 失败时恢复操作按钮并保留原有已遮罩输入，不自动清除有效凭据。

## 错误处理

- 桥接层捕获调度异常，控制器继续负责业务异常的安全映射。
- 预期取消不显示错误，也不写成运行失败。
- 未知异常只记录异常类型，不记录凭据、链接内容或 Telegram 响应正文。
- 错误提示保持可见，直到用户开始下一次相关操作或明确关闭。
- 关闭应用时取消桥接任务，再按现有顺序停止搜索、缩略图、下载调度和 Telegram 连接。

## 测试与验收

### 自动化回归

- 通过真实 `create_application` 连接逐一触发全部零参数信号，断言协程各执行一次且不再产生 qasync `TypeError`。
- 快速重复触发同一动作，断言只存在一个运行任务。
- 覆盖成功、业务异常、意外异常和取消，断言忙碌态均恢复。
- 保留并扩展搜索结果选择、确认、入队和下载调度回归。
- 运行完整 pytest、Ruff、便携版自检和安装版安装/覆盖升级/卸载冒烟。

### 真人路径

使用项目内已保存会话按以下顺序检查：

1. 启动并自动恢复账号，不重复扫码。
2. 进入账号内容页，刷新群组并切换群组。
3. 搜索内容，观察进度并双击预览。
4. 勾选结果，加入下载队列并确认。
5. 观察下载，检查暂停、继续、失败重试和打开目录。
6. 检查设置、在线更新和程序重启后的恢复状态。
7. 检查日志无未处理 qasync 异常，所有新文件均位于项目目录。

系统级 Windows 捕获若继续因权限失败，则使用 Qt 自身事件循环进行相同控件点击、键盘输入、状态断言和逐页截图，不绕过系统权限。

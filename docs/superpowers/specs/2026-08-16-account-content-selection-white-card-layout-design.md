# 账号内容页勾选修复与 W3 白卡布局设计

日期：2026-08-16  
状态：书面规格已确认，等待实施
范围：账号内容页的结果勾选、筛选区、结果表格和局部视觉主题

## 1. 背景与已确认问题

用户在 v0.11.1 的“账号内容”页点击搜索结果首列复选框时，表格只高亮整行，勾选状态和“已选”计数均不变化。实际运行界面和离屏 Qt 探针均稳定复现该问题。

根因位于 `SearchResultTableModel.setData()`：Qt 项目委托传入的勾选值是整数 `2`，现有代码只与 `Qt.CheckState.Checked` 枚举比较。比较结果为假，模型误判为继续保持未选中，因此返回成功但没有更新数据。

现有布局还有三项可见问题：

- 日期、数量和媒体筛选被挤在同一条横线上，最小窗口宽度下日期文字会被截断。
- 结果列使用多项 `ResizeToContents` 自动争抢宽度，长摘要会让日期、大小和状态产生挤压感。
- 深色大面板与背景明度接近，边界主要依靠细描边，卡片层次不明显。

## 2. 已确认的用户选择

- 主要工作方式：批量筛选、连续勾选、加入下载队列。
- 布局方向：A，两层筛选加紧凑表格。
- 视觉方向：W3，浅灰蓝画布、白色卡片、明显多层投影和顶部高光。
- 文字要求：所有标签和固定信息完整显示；摘要只能在自身列内省略，不得越界或挤压其他列。

## 3. 目标与非目标

### 3.1 目标

- 鼠标点击整个“选择”单元格都能切换结果勾选状态。
- 键盘聚焦选择单元格后按空格也能切换，且状态信号只发送一次。
- 不可用或已经入队的结果继续保持不可勾选。
- 在主窗口最小尺寸 `1180 × 720` 和默认尺寸 `1280 × 780` 下，日期、类型、大小、状态及筛选标签都不被截断。
- 结果摘要使用稳定的弹性列；空间不足时只对摘要执行右侧省略，悬停可查看完整摘要。
- 账号内容工作区呈现清晰的白色立体卡片层级，同时保留现有青色主操作色。

### 3.2 非目标

- 不改变其他导航页面的深色主题。
- 不改变 Telegram 搜索、缩略图、预览、队列、数据库或下载逻辑。
- 不改变搜索记录结构、选中状态持久化协议或现有信号参数。
- 本轮不自动修改版本号、创建发布标签或推送正式版。

## 4. 交互设计

### 4.1 勾选值规范化

模型必须同时接受 Qt 委托传入的整数状态和代码直接传入的 `Qt.CheckState`。实现先将值规范化为 `Qt.CheckState`，再判断是否为 `Checked`，不能依赖整数与枚举的隐式相等关系。

模型仍是选中状态的唯一数据源，并继续负责：

- 更新对应 `SearchResult.selected`；
- 发出一次 `dataChanged(CheckStateRole)`；
- 发出一次 `selection_changed(result_id, selected)`；
- 拒绝非首列、不可用和已入队项目的变更。

### 4.2 完整选择单元格点击区

结果表首列使用专用项目委托处理输入：

- 鼠标左键在首列单元格任意位置释放时切换状态，而不要求精确点中 16px 指示框。
- 当前索引位于首列时，空格键切换状态。
- 其他列点击只执行原有行选择；双击预览列的行为保持不变。
- 委托先检查 `ItemIsUserCheckable`，不可用或已入队项目不会改变。

选择列固定宽度为 52px，行高约 78px，因此有效鼠标目标明显大于 44 × 44px。

## 5. 布局设计

### 5.1 页面结构

导航栏和其他页面不变。账号内容页内部使用浅灰蓝画布，并分为三个立体卡片：

1. 左侧“群组与频道”卡片；
2. 右上筛选卡片；
3. 右下结果/历史卡片。

水平分割器继续保留，但左卡片限制在 210–270px，初始宽度约 230px；右侧内容列设置合理最小宽度，避免用户拖动后把结果表压坏。右侧筛选卡片和结果卡片使用 12px 垂直间距，结果卡片获得剩余高度。

### 5.2 筛选区

- 第一行：当前群组标题。
- 第二行：关键词输入框占满剩余宽度，搜索按钮固定宽度。
- 第三行：开始日期、结束日期、数量上限使用 `QGridLayout`；两个日期控件最小宽度约 132px，数量控件约 90px。
- 第四行：媒体类型独占一行；标签和六个复选框保持自然宽度，不与日期控件竞争空间。
- 搜索进度和错误信息仍位于筛选卡片内，出现时只向下扩展，不覆盖结果区。

### 5.3 结果表格

结果列采用可预测的宽度策略：

| 列 | 策略 | 目标宽度 |
| --- | --- | ---: |
| 选择 | 固定 | 52px |
| 预览 | 固定 | 96px |
| 日期 | 固定 | 132px |
| 摘要 | 弹性伸缩 | 获得剩余空间 |
| 类型 | 固定 | 58px |
| 大小 | 固定 | 82px |
| 状态 | 固定 | 64px |

结果行高度从 96px 调整到约 78px，缩略图目标尺寸为 88 × 60px。表格关闭自动换行，使用右侧省略；模型在摘要列的工具提示中提供完整摘要。固定列不得因内容变化自动扩张。

底部“已选数量—全选—反选—加入下载队列”保持同一水平线，并留在结果卡片内，不随表格内容滚动。

## 6. W3 白卡强立体视觉

账号内容页局部主题使用以下层级，不改动全局主题：

- 页面画布：浅灰蓝 `#E3EBF4` 到 `#DCE6F0` 的低对比渐变。
- 卡片背景：Qt `qlineargradient`，从 `#FFFFFF` 过渡到 `#F5F8FC`。
- 主要文字：`#1F2A3D`；次要文字：`#64748B`；表头：`#596B82`。
- 边框：冷灰 `#D3DEE9`，顶部保留近白高光。
- 主操作色：沿用青色系 `#17A8C2`，悬停和选中使用更深的青色。
- 选中行与悬停行只使用浅青背景，不给每一行单独加重阴影，避免批量表格显得拥挤。

Qt 样式表不支持 CSS `box-shadow`，卡片立体感通过 `QGraphicsDropShadowEffect` 实现。仅对三个大卡片添加效果：模糊半径约 36–42px，向下偏移 6–8px，使用透明深蓝灰阴影。布局需为阴影留出外边距，不能让父容器裁切。

## 7. 数据流与兼容性

勾选流程保持为：

`表格委托输入 → SearchResultTableModel.setData() → dataChanged + selection_changed → ContentBrowserPage 更新摘要 → 控制器持久化选择状态`

本设计不引入新的数据库字段、设置项或迁移。现有搜索会话、已选状态、缩略图缓存、群组列表和下载队列均原位兼容。

## 8. 测试与验收

实施遵循测试驱动开发，至少新增以下回归测试：

- 真实鼠标点击复选指示框时，Qt 传入整数 `2`，模型正确变为已选中。
- 点击选择单元格内但不在小指示框上的位置，同样切换状态。
- 首列获得焦点后按空格切换状态。
- 每次交互只产生一次选择信号和一次状态变更。
- 不可用和已入队行对鼠标与键盘操作均无响应。
- 最小窗口和默认窗口下，结果表固定列宽符合约束，摘要列获得剩余空间，水平滚动条不出现。
- 摘要关闭换行并提供完整工具提示。
- 筛选区两个日期和数量控件的最小宽度符合约束。

自动化完成后还需在实际 Windows 窗口验证：

- 点击每一行首列均能勾选并更新底部计数；
- 全选、反选、入队和双击预览无回归；
- 1180 × 720 与 1280 × 780 下无文字越界、标签重叠、列挤压或阴影裁切；
- 白色卡片、浅灰蓝画布和多层阴影层级清楚，长时间浏览仍保持可读性；
- 完整测试、Ruff、冻结包自检和界面截图对比通过。

## 9. 验收结论

只有同时满足“可点击勾选、键盘可用、文字不越界、表格不挤压、W3 卡片立体感清楚、既有业务行为不变”时，本轮工作才算完成。

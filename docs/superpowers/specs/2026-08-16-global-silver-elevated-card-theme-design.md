# 全局白银渐变立体卡片主题设计

日期：2026-08-16  
状态：设计已确认，等待书面规格审核  
范围：主窗口、全部功能页、左右侧栏及所有独立弹窗

## 1. 背景与已确认选择

当前应用大部分界面使用深色背景和接近背景明度的卡片，主要依靠细边框区分层级；只有“账号内容”页使用浅灰蓝画布、白色渐变卡片和 `QGraphicsDropShadowEffect`。用户要求把这种立体感扩展到整个工具，并明确选择以下方向：

- 任务中心、账号内容、自动订阅、健康诊断全部纳入。
- 左侧导航栏、右侧实时概览也改为浅色体系，不保留深色框架。
- 登录、设置、订阅编辑、媒体预览、更新提示和诊断详情等独立弹窗全部纳入。
- 使用“分层强阴影”：主卡片强阴影，内部子卡片中等阴影，输入框、表格和列表保持平整。
- 背景和卡片统一使用白银渐变，继续保留青色作为主操作与选中强调色。

## 2. 目标与非目标

### 2.1 目标

- 全应用形成一致的浅色白银视觉语言，不再出现深色页面或深色弹窗。
- 每个主要内容区域都具有清楚、可见的立体卡片层级。
- 强阴影不能被父布局、分割器、滚动区或窗口边缘裁切。
- 主卡片、子卡片、平面控件三层关系稳定，不因页面复杂度而失去层次。
- 深色文字在银白背景上保持足够对比；选中、悬停、焦点、禁用和错误状态均清晰可辨。
- 保持现有文字省略、工具提示、表格列宽和最小窗口布局，不新增越界或挤压。
- 不改变下载、搜索、订阅、诊断、登录、更新和数据持久化行为。

### 2.2 非目标

- 不给表格行、列表项、输入框、按钮或复选框逐个添加投影。
- 不采用厚重的拟物浮雕或同等强度的全控件阴影。
- 不更改导航结构、业务流程、信号参数、数据库格式或更新协议。
- 本轮不自动修改版本号、创建发布标签或正式发布。

## 3. 全局视觉基础

### 3.1 画布与表面

全局窗口画布使用低对比冷银渐变：顶部接近白色，底部略带冷灰蓝。建议起止颜色为 `#F7F9FC` 与 `#E6EBF2`，既能承托白色卡片，又避免纯白大面积发亮。

导航栏、实时概览和弹窗主体使用独立银白面板。卡片使用垂直白银渐变：

- 顶部高光：`#FFFFFF`；
- 中段银白：`#F8FAFC`；
- 底部冷灰：`#EEF2F6`；
- 边框：`#CCD5DF`；
- 分隔线：`#DCE3EA`。

### 3.2 文字与状态颜色

- 主文字：`#1F2937`；
- 标题：`#172033`；
- 次要文字：`#66758A`；
- 禁用文字：`#9AA8B8`；
- 主操作青：`#17A8C2`；
- 主操作悬停：`#0E8FA8`；
- 浅青选中背景：`#DDF5F8`；
- 成功、警告和错误继续使用绿、琥珀和红色语义，但改为适合浅色背景的边框、文字与淡色底。

所有输入框、日期框、数字框、列表、表格和标签页改为白色或浅银背景。焦点统一使用青色描边，不能依赖深色主题中的发光效果。

## 4. 分层阴影系统

Qt 样式表不支持 CSS `box-shadow`，阴影继续使用独立的 `QGraphicsDropShadowEffect`。每个目标控件必须拥有自己的效果实例，不能复用同一个效果对象。

### 4.1 主卡片强阴影

适用于页面主要内容卡片和弹窗主体：

- 模糊半径：约 34–42px；
- 偏移：向下 7–9px，水平偏移 0–2px；
- 颜色：透明深蓝灰，例如 `rgba(38, 52, 72, 105–125)`；
- 卡片圆角：12–14px；
- 卡片四周至少预留 14px，底部至少预留 18px。

### 4.2 子卡片中等阴影

适用于主卡片内部需要独立分组的详情、统计和诊断区域：

- 模糊半径：约 20–28px；
- 偏移：向下 4–6px；
- 颜色：透明冷灰蓝，例如 `rgba(49, 65, 85, 70–90)`；
- 圆角：10–12px；
- 周围至少预留 9–12px。

### 4.3 平面控件

表格、列表、输入框、按钮、复选框和进度条不挂载图形阴影。它们通过白色表面、银灰边框、顶部高光、浅青选中态和按压色表达交互，避免复杂页面产生层层黑影。

## 5. 页面映射

### 5.1 主窗口框架

- 左侧导航栏成为大型银白面板，使用中等阴影与主内容区分层；品牌区保持青色标识。
- 导航按钮默认透明，悬停使用浅银蓝，当前项使用浅青渐变、青色边框和轻微浮起感。
- 右侧实时概览成为大型银白面板；速度、已完成、队列剩余和当前任务各自作为子卡片。
- 中央页面栈使用透明画布，让各页面共享全局冷银渐变。

### 5.2 任务中心

- “新建下载任务”是主卡片。
- “任务队列”和“任务详情”各自是主卡片，分割器只负责尺寸调整，不承担视觉边框。
- 完整性检查进度使用中等阴影子卡片；任务文件列表作为任务详情卡片内的平面表格，不再增加阴影。
- 现有筛选、列宽、空状态、按钮排列和任务交互保持不变。

### 5.3 账号内容

- 保留“群组与频道、筛选、结果”三卡片布局。
- 用全局白银令牌和统一阴影工具替换页面专用的重复参数。
- 保留固定列宽、摘要省略、完整选择单元格点击和 Space 键切换等 v0.11.2 行为。

### 5.4 自动订阅

- 订阅规则区域是主卡片。
- 规则诊断区域是订阅主卡片内的中等阴影子卡片；运行记录和样本结果各自位于中等阴影分组内。
- 表格本身保持平整，不给每一行加阴影。
- 编辑、立即检查、暂停、删除和测试按钮的业务状态不变。

### 5.5 健康诊断

- 状态横幅使用浅色语义条，不挂载阴影；检测进度和诊断结果分别使用主卡片。
- 底部操作区作为诊断结果主卡片内的中等阴影子卡片。
- 诊断状态的运行、通过、警告和失败颜色改为浅色语义方案。

## 6. 独立弹窗

登录、设置、订阅编辑、媒体预览、更新提示、订阅诊断等弹窗统一加载全局浅色主题。弹窗内容使用一个主表面承载，复杂内容再拆成中等阴影子卡片。

- 登录步骤页保持现有顺序、二维码尺寸、敏感字段遮罩和错误处理。
- 设置页保持字段分组、代理配置和保存行为。
- 媒体预览保持图片、视频、音频和文档预览逻辑，不让强阴影压缩预览区域。
- 更新提示保持签名验证、版本说明和操作按钮状态。
- 弹窗外边距必须容纳主阴影，最小尺寸下不得裁切按钮或文字。

## 7. 代码结构

### 7.1 集中主题

`src/telegram_downloader/ui/theme.py` 继续作为全局颜色与 QSS 的唯一来源。现有 `DARK_STYLESHEET` 名称为兼容调用方可以暂时保留，但其内容改为统一浅色主题；不在各页面复制完整颜色规则。

### 7.2 统一阴影工具

新增聚焦视觉效果的模块 `src/telegram_downloader/ui/effects.py`：

- 定义主卡片与子卡片两个层级；
- 为传入控件创建并安装独立 `QGraphicsDropShadowEffect`；
- 集中保存模糊、偏移和透明度参数；
- 保持函数幂等，重复应用时不会叠加多个效果。

页面模块只声明某个容器属于哪个层级，不直接硬编码阴影颜色和参数。账号内容页现有专用 `_apply_card_shadow()` 迁移到统一工具。

### 7.3 卡片标识

通用主卡片使用统一对象名，子卡片使用统一子层级对象名；仅在确有页面差异时增加范围选择器。导航栏、实时概览和弹窗主体使用明确对象名，便于 QSS 和测试稳定定位。

## 8. 布局与性能约束

- 阴影只安装到静态容器，不安装到重复行、按钮和输入控件。
- 主窗口最小尺寸继续为 `1180 × 720`，默认尺寸继续为 `1280 × 780`。
- 现有表格固定列、弹性摘要列、文字右侧省略和工具提示继续有效。
- 阴影留白通过页面外边距和卡片间距实现，不用额外空白控件挤压业务区域。
- 大型表格所在卡片只保留一层容器阴影，内部不再嵌套同强度效果，降低重绘成本。
- 分割器拖动、页面切换、表格滚动和弹窗缩放时不应出现明显闪烁或卡顿。

## 9. 测试与验收

实施遵循测试驱动开发，先新增失败测试，再修改生产代码。

### 9.1 自动化测试

- 全局 QSS 包含冷银画布、白银卡片、浅色导航、浅色表格和浅色弹窗规则，不再以深色基础色作为窗口背景。
- 阴影工具为不同卡片创建独立效果，主卡片和子卡片的模糊、偏移与透明度符合分层约束。
- 任务中心、统计侧栏、账号内容、自动订阅和健康诊断的主要容器均挂载正确层级效果。
- 登录、设置、订阅编辑、媒体预览、更新提示和订阅诊断弹窗加载浅色主题并包含主表面。
- 账号内容的勾选、列宽、摘要省略和工具提示测试继续通过。
- 主窗口最小尺寸、弹窗最小尺寸、表格列宽和关键标签可见性保持有效。

### 9.2 实际 Windows 验收

逐页检查任务中心、账号内容、自动订阅、健康诊断、左右侧栏和全部弹窗：

- 页面整体无深色残留；
- 白银渐变可见但不过度发灰；
- 主卡片强阴影明显，子卡片阴影弱一级；
- 阴影无裁切、无脏边、无叠黑；
- 文字不越界、不挤压、不贴边；
- 表格、列表、按钮、焦点、禁用和错误状态清楚；
- 页面切换、滚动、分割器拖动和弹窗缩放无明显卡顿。

最后执行完整测试、Ruff、冻结程序自检和关键页面截图对比。本轮完成条件是全应用视觉一致、层级清楚、交互无回归；不包含自动版本提升和正式发布。

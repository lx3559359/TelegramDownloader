# TelegramDownloader v0.7.0 下载任务管理中心设计

日期：2026-08-16

状态：依据用户“后续按建议执行、不再询问”的长期授权确认

## 1. 背景与目标

v0.6.0 已覆盖链接扫描、账号内容搜索、选择下载、断点续传、自动订阅和订阅诊断，但任务中心仍只提供单选暂停、继续、重试全部失败项和打开目录。任务累积后，用户无法快速筛选、批量操作、查看单个媒体状态或整理已完成记录；控制器还会在每次进度刷新时为每个任务分别查询媒体项，任务越多交互越慢。

本版把任务中心升级为可长期使用的下载管理工作台：

- 按关键词和状态快速筛选任务，并显示各分类数量。
- 支持多选任务及批量暂停、继续、重试。
- 展示选中任务的媒体明细、进度、重试次数和安全错误。
- 双击已完成媒体可直接打开文件；任何文件操作都必须通过应用目录路径守卫。
- 已完成任务可安全归档并恢复；归档不删除文件、媒体记录或去重依据。
- 使用单次聚合查询刷新任务摘要，避免当前逐任务查询造成的 N+1 开销。
- 所有数据库、配置、缓存、日志、临时文件和下载内容继续只位于应用目录。

## 2. 方案比较

### 方案 A：下载任务管理中心（采用）

直接改善下载完成前后的高频操作，并能在现有任务数据库、调度器和 Qt 页面上渐进实现。归档采用软删除语义，可恢复且不会破坏媒体去重。

### 方案 B：跨群组全局搜索

可提升内容发现能力，但需要多会话分页、公平调度、全局结果持久化和 FloodWait 管理，网络与账号风险明显更高。本轮不与本地任务管理耦合。

### 方案 C：带宽限速和定时下载

适合网络资源控制，但不能解决任务数量增长后的定位、诊断和整理问题。保留为后续独立能力。

## 3. 用户界面

### 3.1 任务筛选栏

任务队列标题下新增：

- 搜索框：对任务显示标题做不区分大小写的包含匹配；清空后立即恢复。
- 状态筛选：全部、进行中、已暂停、部分失败、已完成、已归档。
- 每个筛选项显示当前数量；“全部”只统计未归档任务，“已归档”单独展示。

进行中包含扫描中、等待中、下载中和等待重试。筛选仅作用于本地模型，不触发 Telegram 请求或数据库写入。新任务或进度刷新后保持当前筛选条件。

### 3.2 多选与批量操作

任务表改为扩展多选。按钮根据全部选中项计算可用性：

- 暂停：至少一个选中任务处于等待中、下载中或等待重试。
- 继续：至少一个选中任务已暂停。
- 重试失败项：至少一个选中任务为部分失败。
- 归档所选：所有选中任务均已完成且尚未归档。
- 恢复所选：所有选中任务均已归档。
- 打开目录：仅选中一个任务时可用。

批量动作只处理符合条件的任务，并在状态栏报告处理数与跳过数；重复任务 ID 会先去重。归档和恢复需要确认对话框，文案明确“不会删除下载文件”。归档运行中、暂停或失败任务不被允许。

### 3.3 任务详情区

任务表下方增加可调整高度的详情区域。单选任务时显示媒体明细：

- 文件名
- 媒体类型
- 状态
- 已下载/总大小
- 进度百分比
- 重试次数
- 安全错误

多选时不加载大量明细，只显示“已选 N 个任务”的批量提示；无选择时显示引导空状态。详情表使用 Qt 模型视图，允许大量行按需绘制，不为每一行创建独立控件。

双击已完成媒体或点击“打开文件”时向控制器发送媒体 ID。控制器从数据库重新读取记录，通过 `PortablePaths.guard` 校验目标路径，确认文件存在后调用 Windows 打开；不存在时只显示明确提示，不修改数据库状态。非完成媒体不能打开文件，但仍可打开任务目录。

### 3.4 刷新与选择保持

0.5 秒进度刷新保留当前筛选、滚动和仍可见的多选项。选中一个任务时只刷新该任务的详情；多选或无选择时不查询媒体明细。任务因筛选条件变化而隐藏后不再作为可操作选择。

## 4. 数据模型与迁移

### 4.1 归档字段

`tasks` 表新增可空 `archived_at TEXT`：

- `NULL`：正常任务。
- UTC ISO 时间：已归档任务。

初始化时检测旧表列并执行幂等迁移。`TaskRecord` 在末尾新增 `archived_at: datetime | None = None`，确保现有位置参数构造仍兼容。便携版原位启动即可迁移，不建立 C 盘数据库或旁路备份。

归档只更新状态为 `COMPLETED` 且 `archived_at IS NULL` 的任务。恢复只清空已归档任务的 `archived_at`。`media_items` 不删除，因此：

- 下载文件保留。
- 任务和媒体详情可恢复。
- `(peer_ref, message_id, media_id)` 唯一约束继续防止重复入队。
- 普通任务统计默认排除归档项。

### 4.2 聚合快照

新增只读 `TaskSnapshot`，包含任务记录、媒体总数、完成数、已下载字节、已知总大小、未知大小数量及一个安全错误摘要。

`TaskRepository.list_task_snapshots(include_archived=True)` 使用一条 SQLite 聚合查询和关联子查询返回全部摘要，替代控制器当前 `list_tasks()` 后对每个任务调用 `list_items()` 的 N+1 流程。排序仍为创建时间倒序，结果语义与现有任务表一致。

详情继续使用 `list_items(task_id)`；新增 `get_item(item_id)` 用于打开文件前重新校验。

## 5. 控制器与调度

控制器新增以下边界：

- `pause_tasks(task_ids)`：同步暂停符合条件的任务。
- `resume_tasks(task_ids)`：并发恢复已暂停任务，复用调度器现有活动任务去重。
- `retry_failed_tasks(task_ids)`：并发重试部分失败任务。
- `archive_tasks(task_ids)` 与 `restore_tasks(task_ids)`：调用仓库的条件更新并刷新模型。
- `select_task_details(task_id | None)`：只加载当前单选任务的媒体明细。
- `open_media_file(item_id)`：重新取记录、路径守卫、存在性检查和 Windows 打开。

单任务旧方法保留为兼容包装。所有异常经现有 `_safe_error` 脱敏；状态栏不显示目标绝对路径、群组内部标识或 Telegram 原始异常。

归档不触碰调度器。仓库的条件更新和控制器二次状态检查共同避免进度刷新竞态下误归档活动任务。

## 6. 性能与可靠性

- 任务摘要刷新固定为一次数据库读事务，不随任务数增加数据库连接次数。
- 只有单选任务加载媒体明细；详情模型原位重置，不扫描文件系统。
- 筛选在内存中执行，输入响应不等待数据库或 Telegram。
- 批量动作对任务 ID 去重，并沿用调度器对同一活动任务的去重。
- 关闭程序继续等待现有下载任务安全暂停；任务详情不创建后台线程或持久对象。
- 归档、恢复和迁移使用 SQLite 事务，失败时不留下半批状态。

## 7. 隐私与路径边界

- 不保存新的 Telegram 消息正文、缩略图或账号信息。
- 任务搜索关键词仅驻留当前界面内存，不写设置或日志。
- 打开文件和目录前使用 `PortablePaths.guard`；数据库中的越界路径会被拒绝。
- 归档仅修改 `<应用目录>/data/database/tasks.sqlite3`。
- 发布包继续排除 `data/`、`downloads/`、日志、数据库和加密会话。

## 8. 错误与空状态

- 没有匹配任务：显示“没有符合当前筛选的任务”，保留筛选控件。
- 多选：详情区显示批量提示，不误展示旧任务明细。
- 文件缺失：显示“本地文件不存在；当前操作不会修改任务记录”，不自动删除、改状态或承诺无法执行的重试。
- 越界路径：显示安全错误并记录脱敏事件，不打开任何路径。
- 归档状态在动作前变化：跳过该项并报告数量。
- 数据库迁移失败：沿用启动错误边界，不覆盖旧数据库。

- 仓库：旧表迁移、归档/恢复条件、归档任务仍参与媒体去重、聚合快照数值与排序、单条媒体读取。

- 包装：版本、PyInstaller 隐式导入、自检和 ZIP 隐私合同。

### 9.2 真实化 QA

使用项目内现有 DPAPI 加密会话的隔离副本，不读取或输出凭据、群名、任务标题或文件名：

- 启动后复用会话，不出现二维码。
- 注入仅位于隔离数据库和下载目录的合成任务/文件，验证六种筛选、关键词、多选按钮、详情、双击打开拦截、归档、重启、恢复和去重。
- 记录只包含数量与布尔结果，清理全部合成数据。
- 在 1280×780 和最小 1180×720 尺寸抓图检查筛选栏、任务表、详情表和动作区无重叠或裁切。
- 完成三轮全量测试、Ruff、便携包自检、安装包升级/卸载保留和 ZIP 隐私检查。

## 11. 本轮不包含

- 删除下载文件或不可恢复地删除任务记录。
- 单个媒体手动重试、文件哈希校验或损坏文件自动修复。
- 跨群组全局搜索、复杂布尔关键词、带宽限速、定时下载或系统通知。
- Windows 后台服务、计划任务或任何 C 盘业务数据目录。

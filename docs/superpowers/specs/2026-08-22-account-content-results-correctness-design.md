# 账号内容结果排版、筛选与缩略图修复设计

## 背景

“账号内容”页目前有四个相关问题：搜索结果表把“来源”固定为 92px，并把除“摘要”外的大多数列设为固定宽度，导致会话标题和结果内容被强制省略；全局复选框样式只为选中状态填充青色，没有绘制勾号；相册展开结果未经搜索媒体类型再次过滤，因而只选择“视频”时仍可能保存图片；视频结果虽然进入了缩略图请求链路，但失败后只显示纯色方块，且网关没有明确选择静态图片缩略图或尝试较小候选图。

本轮把这些问题作为一个独立子项目修复，不同时扩展设置页，以便筛选正确性、缩略图行为和表格响应式布局可以独立验证。

## 目标

- 在应用允许的最小窗口宽度下，让结果的来源标题获得主要横向空间，不再被窄固定列挤压。
- 媒体类型复选框在选中时显示清晰的白色勾号，并保留当前青色主题。
- 搜索结果严格满足持久化查询中的媒体类型集合，包括相册展开项和旧搜索记录。
- 视频优先显示 Telegram 提供的静态缩略图；确实没有可用图片时显示带播放标志的明确占位图。
- 保留渐进式结果、缩略图并发合并、失败冷却、相册整体分页和选择/入队语义。

## 非目标

- 不下载完整视频来本地截帧。这样会产生隐藏的大流量和长等待，违背缩略图轻量加载的目的。
- 不改变 Telegram 关键词搜索、日期范围、数量上限或相册不拆分规则。
- 不在本轮重构任务中心、自动订阅或设置页。
- 不改变已经入队任务的目标文件和下载状态。

## 方案取舍

### 方案一：只扩大“来源”列

改动最小，但会继续和摘要、日期、大小等固定列争抢空间；窗口变窄或标题变长时问题会再次出现。

### 方案二：合并“来源”和“摘要”为“内容”列

结果列调整为“选择、预览、内容、日期、类型、大小、状态”。内容列使用剩余空间，在同一单元格中把来源标题作为主信息、摘要作为次信息。日期使用两行紧凑显示。该方案在不减少信息的前提下消除两个文本列之间的竞争，是本轮采用的方案。

### 方案三：结果改成卡片列表

最自由，但会重写表格模型、键盘选择、批量勾选和可访问性行为，超出一次缺陷修复的合理范围。

## 界面设计

### 结果表

表格保留整行选择、隔行底色、78px 最小行高和 88×60 缩略图。列布局改为：

| 列 | 模式 | 目标宽度 | 内容 |
| --- | --- | ---: | --- |
| 选择 | 固定 | 44px | 可勾选状态 |
| 预览 | 固定 | 96px | 缩略图或媒体占位图 |
| 内容 | 拉伸 | 剩余空间 | 来源标题和消息摘要 |
| 日期 | 固定 | 96px | 第一行日期，第二行时间 |
| 类型 | 固定 | 56px | 图片、视频等 |
| 大小 | 固定 | 82px | 格式化文件大小 |
| 状态 | 固定 | 68px | 可选择、已入队或不可用 |

“内容”列由专用委托绘制：来源标题使用主文字颜色和较高字重，允许换行且不主动省略；摘要使用次要颜色并在一行内省略。行高至少容纳缩略图，并在标题确实需要多行时按标题高度增加。完整来源标题、摘要和原始文件名继续通过工具提示提供。标题高度计算按行缓存，并在表格宽度或模型内容变化时失效，避免滚动时重复计算。

### 媒体类型勾选

新增可复用的主题复选框绘制类，在 Qt 完成现有复选框绘制后，根据选中状态在 indicator 中绘制抗锯齿白色勾号。账号内容页的六个媒体类型控件使用该类；未选中、禁用、焦点和文字布局仍由 Qt 与现有样式表处理。

本轮不把所有应用复选框一次性替换，避免产生无关视觉变更。后续设置中心可以复用同一控件。

### 视频占位图

媒体回退图标不再是纯色方块。视频回退图标使用主题紫色底、居中的白色播放三角和轻微边框；图片、音频、语音、文档和压缩包继续使用各自颜色与可识别符号。占位图只表示 Telegram 没有提供可解码的缩略图，不伪装成真实画面。

## 筛选正确性

网关返回的直接搜索命中已经按 `query.filters.media_kinds` 过滤，问题发生在 `ContentBrowserService` 展开相册后。修复在服务层建立单一持久化前置条件：任何准备去重、分页和写入目录库的 `RemoteSearchHit`，其 `remote.kind` 必须属于当前搜索会话的媒体类型集合。

数据流为：

1. 网关取得直接搜索页并完成初步类型过滤。
2. 页面可继续渐进显示直接命中，因为这些命中已经满足过滤条件。
3. 服务并发展开命中的相册。
4. 直接命中与相册成员合并后，统一按会话媒体类型集合再次过滤。
5. 过滤后的结果才进入去重、相册单元分组、页面/总量限制、队列重复检查和数据库提交。
6. 稳定结果批次替换临时批次，界面中不会短暂加入不匹配的相册成员。

为处理旧版本已经保存的错误记录，打开搜索记录时按该记录持久化的媒体类型集合进行一次一致性清理：从搜索结果表删除所有不匹配项并重新计算结果数。下载任务与搜索结果是独立记录，因此已由这些结果创建的任务和文件保持不变。清理只作用于目标账号和目标搜索记录。

## 视频缩略图管线

`TelethonGateway.load_thumbnail` 从重新获取的当前消息中验证媒体 ID 后，读取媒体可用缩略图候选。候选处理规则为：

1. 排除 `VideoSize`、空尺寸、路径轮廓等不能作为静态栅格图显示的类型。
2. 按静态图片的像素面积或字节大小从大到小排序。
3. 依次请求候选缩略图，拒绝空内容、超过缓存单项上限或不能识别为 JPEG、PNG、WebP 的内容。
4. 返回第一张有效图片；较大候选不可用时自动尝试较小候选。
5. 没有有效候选时返回 `None`，由界面显示对应媒体占位图。

缩略图网关接口增加单项字节上限参数，服务传入 `ThumbnailCache.max_item_bytes`，避免先下载并返回一张注定无法缓存的图片。缓存键、最大总量、LRU 清理、同键并发请求合并和失败冷却保持不变。

访问失败、文件引用过期或图片解码失败不会把媒体标为不可用，也不会弹出逐行错误；服务记录现有冷却状态并展示占位图。用户稍后重新打开或冷却到期后仍可重试。

## 组件边界

- `ui/content_browser.py`：配置新列布局、安装内容绘制委托和主题复选框。
- `ui/content_models.py`：提供内容列需要的来源标题、摘要、日期分行文本和媒体回退图标数据。
- 新的轻量 UI 模块：封装带勾号复选框及结果内容委托，避免继续增大页面构造文件。
- `content_browser.py`：统一过滤直接命中与相册成员，并协调旧记录一致性清理和缩略图字节上限。
- `gateway.py`：选择和下载可显示的静态缩略图候选。
- `catalog.py`：提供账号与搜索记录双重限定的一致性清理操作，并同步结果计数。

UI 层不决定媒体过滤规则，网关不决定搜索记录持久化，目录库不理解 Qt 展示细节。

## 测试设计

### 服务与目录库

- 构造只允许视频的查询和包含视频、图片的混合相册，先观察现有测试失败，再断言最终结果、数据库记录、结果计数和稳定批次都只含视频。
- 分别覆盖单会话搜索和全账号搜索，确认 `(peer_ref, grouped_id)` 相册隔离保持不变。
- 构造旧搜索记录中的错类型结果，断言打开记录后只清理该账号、该搜索，不影响已创建任务或其他历史。

### 网关与缓存

- 提供视频型、超限静态图、有效较小静态图和空候选，断言网关跳过前两者并返回有效图片。
- 验证媒体 ID 改变、访问失败、无缩略图和非图片字节仍安全返回或映射现有错误。
- 验证同键并发合并、失败冷却和缓存命中测试继续通过。

### UI

- 在最小窗口宽度装载长来源标题和长摘要，断言内容列为拉伸列、横向滚动条不出现、标题绘制区域不再受 92px 固定宽度限制。
- 渲染选中和未选中的媒体类型控件，断言只有选中状态在 indicator 内出现白色勾号像素。
- 断言视频无缩略图时返回非空、带播放标志的回退图标；缩略图到达后仍替换回退图标并更新已打开预览。
- 保留选择、全选、反选、入队、渐进批次和可见行缩略图请求回归。

## 验收标准

1. 1280×780 默认窗口和 1180×720 最小窗口下，结果表不出现横向滚动条，来源标题使用内容列的主要空间并可通过换行完整阅读。
2. 选中“视频”后，新搜索、继续搜索、相册展开和旧记录恢复均不显示图片结果。
3. 六个媒体类型选项的选中状态均显示清晰勾号。
4. 有 Telegram 静态缩略图的视频显示真实图片；无可用图时显示视频播放占位图。
5. 相关定向测试、完整测试套件、静态检查和打包契约均通过。

# TelegramDownloader 托盘后台、系统通知与下载时段设计

状态：用户要求按既定顺序逐项完成 P1 功能；本文只定义第 4 项，后续高级订阅、批量链接、全局媒体调度和命名模板不进入本轮实现。

## 1. 背景与目标

当前主窗口的关闭事件会隐藏窗口并立即启动完整安全退出：异步动作收敛、订阅调度器停止、下载在安全边界暂停、Telegram 断开，随后进程退出。因此自动订阅只能在主程序可见运行期间工作，用户也无法在关闭窗口后收到任务完成、失败或订阅命中的 Windows 通知。

本轮目标是在不引入 Windows 服务或第二后台进程的前提下，让现有主进程可靠驻留托盘：窗口关闭后下载、连接监视和自动订阅继续运行；用户可明确退出；下载可按每周时段自动暂停和恢复；关键事件通过隐私安全的系统通知呈现。

## 2. 方案比较与决策

### 方案 A：主进程托盘常驻（采用）

复用现有 Qt 事件循环、Telegram 会话、下载调度器和在线更新事务。窗口只是主进程的一个可见表面，关闭窗口不再等同于结束进程。优点是状态单一、无需进程间同步、便携版和安装版行为一致；代价是用户退出 Windows 后不能继续运行。

### 方案 B：独立后台助手

界面关闭后由独立助手持有订阅和下载状态。它能让界面进程独立重启，但需要 IPC、会话所有权、数据库写入仲裁和双进程升级协议，显著扩大故障面。

### 方案 C：Windows 服务或计划任务

可以在没有主窗口时运行，但 Windows 服务无法直接使用当前交互式用户的托盘与登录流程，DPAPI、Telegram 二次验证、便携安装和升级都需要额外架构，不符合本轮增量目标。

本轮采用方案 A。后台运行只持续到用户明确退出、系统注销/关机或在线更新要求退出，不承诺在 Windows 用户未登录时运行。

## 3. 用户可见行为

### 3.1 关闭、隐藏与退出

- 系统托盘可用且“关闭到托盘”开启时，点击窗口关闭按钮只隐藏主窗口，不触发控制器关闭。
- 第一次关闭到托盘后显示一次通用提示，说明程序仍在后台运行以及如何彻底退出；该提示是否已显示保存在应用目录的设置文件中。
- 双击托盘图标或选择“显示主窗口”会恢复、置前并激活现有窗口。
- 托盘菜单包含：显示/隐藏主窗口、暂停全部下载、继续可运行下载、立即检查到期订阅、打开下载目录、彻底退出。
- “彻底退出”、Windows 注销/关机以及在线更新替换运行时，继续调用现有幂等安全关闭流程。重复退出请求不会启动第二个关闭任务。
- 系统托盘不可用时，“关闭到托盘”设置在界面中标记不可用；窗口关闭回退为现有安全退出，不允许形成无窗口且无法唤回的进程。

### 3.2 单实例唤醒

现有互斥量继续阻止第二个应用实例。主实例额外启动基于 `QLocalServer`/`QLocalSocket` 的本机命名管道，只接受固定的 `activate` 消息。

第二次启动发现互斥量已存在时，先向主实例发送激活消息；主实例显示并激活窗口。发送失败才回退为“程序已经在运行”的安全提示。命名管道不传输账号、路径、链接或其他用户数据，也不创建持久业务文件。

### 3.3 开机启动

- “登录 Windows 后后台启动”默认关闭，只能由用户在设置中明确开启。
- 正式冻结程序通过当前用户的 `HKCU\\Software\\Microsoft\\Windows\\CurrentVersion\\Run` 写入唯一固定值，命令由当前可执行文件绝对路径和固定参数 `--background` 组成，不需要管理员权限。
- 关闭该设置时立即删除对应值；路径改变后，应用在下一次前台启动时校正自己的值。
- 源码开发模式不写启动项，设置界面显示只有正式打包程序可用。
- 该注册表值属于用户主动启用的 Windows 启动集成，不保存设置、凭据、任务或 Telegram 数据；所有业务数据仍只位于应用目录。

### 3.4 后台启动

新增 `--background` 命令行参数。后台启动不显示启动提示和主窗口，但仍完成本地数据库初始化、任务恢复、账号恢复、连接监视、订阅调度和在线更新检查。若登录失效或发生需要用户处理的错误，通过托盘通知提示；用户点击通知后显示对应页面。

如果托盘不可用，`--background` 不允许静默运行：程序显示主窗口并给出固定说明。

## 4. 系统通知

### 4.1 通知事件

通知覆盖以下终态或需人工处理事件：

- 下载任务全部完成；
- 下载任务部分失败；
- 自动订阅发现新媒体并创建任务；
- Telegram 登录失效；
- 磁盘空间不足导致下载暂停；
- 下载时段开始或结束导致自动恢复或暂停。

暂停、进度刷新、普通重试和每个媒体项完成不单独通知，避免噪声。

### 4.2 隐私与合并

- 锁屏可见通知只包含事件类别、任务/媒体数量和通用操作提示，不包含账号、频道、群组、消息摘要、搜索词、原始文件名或绝对路径。
- 同类事件在 5 秒合并窗口内聚合为一条通知，例如“3 个下载任务已完成”。
- 每个任务终态只通知一次；控制器的周期刷新不能重复触发同一通知。
- 点击通知显示主窗口并导航到任务、订阅或登录页面；通知正文不承担诊断详情，具体安全错误仍在应用内查看。
- 通知被 Windows 禁止、托盘暂时失效或通知 API 抛错时，只记录脱敏日志，不改变任务、订阅或连接状态。

### 4.3 事件来源

新增纯数据 `ApplicationEvent`，由下载调度器终态回调、订阅任务创建回调、授权恢复流程、磁盘不足处理和下载时段控制器产生。`NotificationService` 负责去重、聚合和隐私安全文案；Qt 托盘适配器只负责展示与点击回调。业务服务不直接依赖 Qt。

## 5. 下载时段

### 5.1 设置模型

设置增加独立的 `DownloadScheduleSettings`：

- `enabled`：默认 `false`；
- `weekdays`：周一至周日的非空集合，默认每天；
- `start_minute`、`end_minute`：本地时间 0–1439；
- 起止时间相同表示所选日期全天开放；
- 开始早于结束表示同日窗口；开始晚于结束表示跨午夜窗口，结束段归属于开始日。

时间计算使用系统当前本地时区。系统时钟、时区或夏令时变化后，每次定时器唤醒都从当前墙钟重新判断，不依赖累计睡眠推算边界。

### 5.2 调度行为

- 时段外关闭下载调度器的“新任务准入”；新任务和订阅创建的任务保持排队，不丢失优先级。
- 时段结束时，当前活动任务在现有安全分块边界暂停；`.part`、确认字节和哈希状态按现有语义持久化。
- 任务新增可空的暂停原因：`user` 或 `schedule`。用户暂停优先于时段暂停。
- 时段开始时只恢复暂停原因为 `schedule` 的任务；用户手动暂停、部分失败和归档任务不会自动恢复。
- 用户在时段外点击继续时，任务可以转回排队，但不会开始下载；界面显示下次允许下载的时间。用户若要立即下载，应关闭下载时段设置，不增加一次性绕过状态。
- 自动订阅、会话恢复、搜索、诊断和在线更新不受下载时段限制；订阅可继续发现并排队。
- 应用在时段外启动时，先关闭调度准入再恢复队列，避免启动瞬间误下载一个分块。

### 5.3 数据迁移

任务表增加可空 `pause_reason` 列，旧任务迁移后为 `NULL`。旧版 `PAUSED` 任务视为用户暂停，不会因时段开始自动恢复。所有状态变更继续在现有 SQLite 事务内完成。

## 6. 组件与职责

新增或调整以下边界：

- `background.py`：`BackgroundModeController`，拥有关闭到托盘、窗口显示、托盘菜单和真正退出编排。
- `activation.py`：本机激活服务与第二实例客户端，不承载业务数据。
- `notifications.py`：应用事件、去重聚合、隐私安全文案和通知路由；核心部分不依赖 Qt。
- `download_schedule.py`：纯函数时段判断、下一边界计算和 `DownloadScheduleController`；时钟与定时器可注入。
- `autostart.py`：可注入的当前用户启动项适配器，只拥有一个固定注册表值。
- `settings.py`：新增后台、通知、开机启动和下载时段设置，缺失字段按兼容默认值读取。
- `scheduler.py`：增加准入开关、时段暂停和只恢复时段暂停任务的最小接口；本轮不改为跨任务媒体调度。
- `repository.py`/`domain.py`：持久化暂停原因并保持旧数据库幂等迁移。
- `app.py`：只负责构造并连接上述组件；不把托盘、通知和时段状态机继续堆入 `AppController`。

设置界面改为“常规”和“后台与通知”两个页签。后者包含关闭到托盘、系统通知、开机启动和下载时段；禁用时段时隐藏或禁用星期与时间控件。设置保存先验证模型，再更新启动项和运行时控制器；启动项写入失败时不保存“已启用”的假状态。

## 7. 错误处理与恢复

- 托盘创建失败：记录脱敏原因，回退到普通窗口生命周期。
- 启动项写入或删除失败：设置保存失败并显示可操作提示，其他设置保持旧值。
- 命名管道冲突或激活失败：不启动第二业务实例，显示现有安全提示。
- 时段暂停过程中进程异常退出：下次启动通过 `.part` 与任务状态恢复；暂停原因决定是否自动恢复。
- 系统休眠跨过时段边界：唤醒后立即重新计算状态并执行一次幂等转换。
- 通知失败：不传播到业务事件生产者，不影响下载和订阅。
- 在线更新请求退出：绕过关闭到托盘，调用真正退出并等待现有更新安全关闭流程。

## 8. 测试与验收

### 8.1 自动化

- 关闭窗口只隐藏且不调用 `controller.shutdown`；托盘“退出”只调用一次安全关闭。
- 托盘不可用、更新退出、重复退出和系统退出路径均有回归测试。
- 第二实例激活隐藏窗口；管道失败不启动第二控制器。
- 设置缺失字段迁移、非法星期/分钟拒绝、源码模式禁用启动项、注册表启用/禁用/路径校正使用假适配器测试，不接触真实用户注册表。
- 同日、跨午夜、全天、星期边界、周日跨周、时区变化、休眠跨边界和注入时钟均有确定性测试。
- 时段关闭阻止新任务准入，活动任务安全暂停；时段打开只恢复 `schedule`，不恢复 `user`。
- 旧数据库暂停任务迁移后保持用户暂停语义。
- 通知终态只发送一次，5 秒内同类合并；通知文案隐私字段扫描为零。
- 背景启动不显示主窗口但启动服务；无托盘时回退显示窗口。
- 完整 pytest、Ruff、源码自检、冻结程序冒烟和安装器升级/卸载数据保留测试通过。

### 8.2 Windows 人工验收

- 正式安装版和便携版分别检查托盘图标、关闭隐藏、双击恢复、菜单操作和真正退出。
- 开启开机启动后重新登录 Windows，程序直接进入托盘；关闭设置后启动项消失。
- Windows 通知开启和关闭两种系统状态下，下载、失败、订阅和登录失效行为均不受影响。
- 使用短测试时段验证边界暂停、跨午夜判断、重启后恢复和手动暂停不被自动恢复。
- 在线更新从前台和托盘后台触发时均能真正退出、替换、健康检查并重启。

## 9. 验收标准

1. 关闭窗口后进程、下载、连接监视和订阅继续运行，且窗口可从托盘恢复。
2. 用户可以明确彻底退出，安全关闭仍等待异步动作和下载持久化边界。
3. 第二次启动会唤醒隐藏实例，不创建第二套数据库或 Telegram 连接。
4. 开机启动默认关闭，启用和关闭均可逆、无需管理员权限。
5. 下载完成、部分失败、订阅命中、登录失效、磁盘不足和时段转换产生去重通知。
6. 系统通知不包含账号、会话、来源名称、消息、搜索词、文件名或路径。
7. 下载时段支持星期、同日、全天和跨午夜窗口。
8. 时段外不启动新下载，活动下载在安全边界暂停，订阅仍可排队。
9. 时段开始只恢复时段自动暂停任务，不改变用户手动暂停任务。
10. 旧设置、任务数据库、登录会话、下载文件、在线更新和非 C 盘数据边界保持兼容。

## 10. 本轮不包含

- Windows 服务、计划任务、独立后台下载进程或用户未登录时运行；
- 第 5 项复杂订阅表达式与历史补抓；
- 第 6 项批量链接导入；
- 第 7 项跨任务全局媒体并发；
- 第 8 项目录和命名模板；
- 远程控制、移动端推送、邮件、Webhook 或浏览器扩展；
- 绕过 Telegram 权限、内容保护、FloodWait 或平台限制。

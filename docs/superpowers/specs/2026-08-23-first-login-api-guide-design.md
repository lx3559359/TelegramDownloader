# TG 快取首次登录 API 获取指南设计

日期：2026-08-23

状态：已确认，待实施

## 1. 背景

TG 快取当前首次登录页提供 API ID、API Hash、代理和“保存并生成二维码”操作，但应用内只有“从 my.telegram.org 获取”的占位提示。README 虽然列出基础步骤，首次使用者仍需要离开当前上下文自行判断官网入口、确认码位置、`API development tools`、创建应用表单和 API 字段对应关系。

Telegram 要求第三方客户端使用用户自己的 API ID 与 API Hash。官方流程是：先使用官方 Telegram 应用注册账号，再登录 `my.telegram.org`，进入 `API development tools` 填写表单并取得 `api_id`、`api_hash`。官网登录确认码发送到 Telegram，而不是短信；当前每个手机号只能关联一个 API ID。参考：

- Telegram 官方申请说明：<https://core.telegram.org/api/obtaining_api_id>
- Telegram 应用管理入口：<https://my.telegram.org/apps>

## 2. 目标

- 没有 API 凭据的用户第一次打开登录窗口时，直接看到完整、可执行的申请流程。
- 用户可以从指南安全地在系统默认浏览器打开 Telegram 官方页面。
- 用户知道创建应用表单各字段如何填写，并能识别 `api_id` 与 `api_hash`。
- 已有 API 的用户可以折叠指南并继续快速登录；以后仍可随时重新展开。
- 指南不削弱现有 API Hash 掩码、DPAPI 存储、扫码授权、手机号备用登录和两步验证边界。

## 3. 非目标

- 不在程序内嵌 Telegram 网页或代替用户登录官网。
- 不读取网页登录手机号、确认码、Cookie、浏览记录或剪贴板。
- 不自动创建 Telegram 应用，不自动抓取或填入 API ID/API Hash。
- 不内置、共享或推荐公共 API 凭据。
- 不改变代理、二维码、手机号验证码、两步验证、候选账号切换或会话持久化协议。
- 不把指南独立放入设置页；本轮入口始终位于登录窗口。

## 4. 已选择方案

采用“登录页内置可折叠分步指南”。

未选择的方案：

- 独立前置引导页：内容空间充分，但增加页面切换，用户在官网与程序间返回时更容易迷失。
- 左右双栏：信息直观，但会显著增加窗口宽度，在小屏幕和 125% 缩放下不稳健。

内嵌方案保持“获取 API → 填写凭据 → 生成二维码”处于同一上下文，且对原登录状态机影响最小。

## 5. 用户流程

### 5.1 首次配置

1. 用户在没有完整 API ID/API Hash 的情况下进入登录窗口。
2. “第一次使用？约 3–5 分钟获取 API”指南默认展开。
3. 用户阅读步骤并点击“打开 Telegram API 申请页面”。
4. 系统默认浏览器打开 `https://my.telegram.org/apps`；登录窗口保持打开，已填写字段保持不变。
5. 用户在官网完成登录、进入 `API development tools`，创建或查看个人应用。
6. 用户把 `api_id` 和 `api_hash` 粘贴到指南下方原有输入框。
7. 用户按现有流程保存凭据、连接 Telegram 并生成二维码。

### 5.2 已有凭据

- 当 API ID 大于零且 API Hash 非空时，指南默认折叠，仅显示“如何获取 API ID / Hash”标题和展开按钮。
- 用户可随时展开或再次收起；展开状态仅属于当前窗口，不写入设置或秘密存储。
- 展开、收起和打开网页不得改变 API、代理或登录输入值。

### 5.3 外部浏览器失败

- 系统浏览器启动返回失败时，指南内部显示“无法打开系统浏览器，请复制官方网址后手动打开”。
- 同一区域显示完整 HTTPS 域名和“复制官方网址”按钮。
- 失败不关闭窗口、不切换登录页、不清空输入、不触发 Telegram 连接。

## 6. 指南内容

指南使用五个编号步骤：

1. **准备 Telegram 账号**：先在官方 Telegram App 注册并保持登录，使用当前有效手机号。
2. **打开官方申请页**：按钮明确显示 `my.telegram.org/apps`，并说明网页属于 Telegram，本程序不读取网页登录内容。
3. **登录并进入开发工具**：手机号使用国际格式；中国大陆号码示例只展示格式 `+86…`，不展示完整虚构号码；确认码在 Telegram 消息中，不是短信。登录后选择 `API development tools`。
4. **创建或查看个人应用**：提供非敏感示例：
   - App title：`TG Quick Fetch Personal`
   - Short name：`tgquickfetch`
   - Platform：`Desktop`
   - Description：`Personal media download manager`
   - 如果官网显示 URL 或其他字段，用户按网页当前要求填写；指南不伪造网站地址，也不把可能变化的可选性写死。
5. **复制凭据**：说明 `api_id` 是纯数字，`api_hash` 是较长字符串，分别粘贴到下方对应字段。

指南底部显示安全提醒：API Hash 与密码类似，不应截图、分享或提交到公开网站；必须遵守 Telegram API 条款，不得用于刷量、垃圾消息或其他滥用行为。

### 6.1 常见问题

- **没有收到确认码**：检查已登录 Telegram App 中的 Telegram 服务消息；不要只等待短信。
- **页面打不开**：检查网络或代理；程序只提供复制官方地址，不绕过 Telegram 访问限制。
- **账号已经创建过 API**：再次进入 `API development tools` 查看现有凭据，不反复创建应用；官方当前说明每个手机号只能关联一个 API ID。
- **字段提交失败**：核对网页提示并使用简短的英文或数字示例；不把未经官方公开确认的精确长度限制写入应用。
- **API Hash 疑似泄露**：停止分享，不在聊天、截图或日志中继续暴露，并通过 Telegram 官方渠道处理。

## 7. 界面与可访问性

- 登录窗口采用当前 TG 快取主题；凭据页整体增加纵向滚动，禁止横向滚动。
- 指南位于“步骤 1 / 4 · API 凭据与网络”和 API 表单之间。
- 展开标题包含清晰的“展开指南/收起指南”文字，不只依赖箭头或颜色表达状态。
- 步骤卡片保持单列阅读顺序；字段示例使用可复制文本，但不得伪装成真实输入框。
- API 输入、代理字段和“保存并生成二维码”按钮仍在同一凭据页，展开后通过纵向滚动到达。
- 登录窗口保持适中宽度；凭据页视口高度依据当前屏幕可用区域限制，100% 和 125% 缩放下不得超出屏幕。
- Tab 顺序依次经过指南切换、打开官网、备用网址复制、API 表单和提交按钮；隐藏内容不进入 Tab 顺序。
- 按钮和折叠区域设置可访问名称；状态变化可由屏幕阅读器识别。

## 8. 组件边界

### 8.1 `ApiCredentialGuide`

新增 `src/telegram_downloader/ui/api_guide.py`，只负责：

- 官方 URL 常量与显示文本。
- 展开/折叠状态及五步内容。
- 打开系统浏览器和复制备用网址的用户动作。
- 浏览器启动失败的局部反馈。

组件通过可替换的打开 URL 与复制文本边界调用系统能力，使测试不启动真实浏览器、不修改真实剪贴板。默认生产边界分别使用 Qt 的系统浏览器接口和应用剪贴板。

组件公开最小行为接口：设置“是否已有完整凭据”、查询/切换展开状态。它不接收也不保存 API ID、API Hash、手机号、验证码、密码或会话。

### 8.2 `LoginDialog`

`src/telegram_downloader/ui/login.py` 继续拥有 API、代理和授权表单。改动仅包括：

- 在凭据页组合 `ApiCredentialGuide`。
- 为凭据页提供纵向滚动容器。
- `set_saved_credentials()` 在凭据页第一次显示前，根据 API ID 与 API Hash 是否完整设置指南初始状态；用户手动展开或收起后，后续字段回填不得覆盖当前选择。

凭据提交信号和所有后续登录页面保持现有契约。

## 9. 数据与安全边界

- 指南展开状态不持久化，不新增数据库字段或设置键。
- 官方 URL 是固定 HTTPS 常量，只允许 `https://my.telegram.org/apps`。
- 网页始终由系统默认浏览器打开；应用不载入 WebView、不接收网页回调。
- 不自动读取剪贴板或把剪贴板内容填入敏感字段。
- API Hash 保持密码模式；指南文本、错误、测试输出和日志不得包含真实 API ID/API Hash、手机号、确认码、二维码令牌、两步验证密码或会话字符串。
- API Hash、代理密码和会话仍按现有 Windows DPAPI 方案保存；本功能不改变存储格式。

## 10. 错误处理

- 系统浏览器打开失败：显示局部错误和复制入口，表单继续可用。
- 剪贴板复制失败：保留可选择的完整 URL，并显示“复制失败，请手动选择网址”。
- 官网不可访问或返回业务错误：应用不猜测原因、不代替 Telegram 校验；指南提供网络、确认码和已有 API 三类固定排查说明。
- 指南组件自身异常不得触发二维码、注销当前会话、清空凭据或关闭登录窗口。
- 原有 API 字段验证和安全错误映射继续负责凭据提交错误。

## 11. 测试设计

### 11.1 组件测试

- 无凭据时默认展开；完整凭据时默认折叠；只有一项凭据时仍展开。
- 展开、收起和再次打开不修改登录表单值。
- 五步标题、字段示例、确认码来源、安全提醒和官方域名均存在。
- 点击打开按钮只向系统边界传递唯一官方 HTTPS URL。
- 模拟系统浏览器失败后显示备用网址和复制按钮；模拟复制失败后 URL 仍可选择。
- 隐藏状态下详细内容不可见且不参与键盘焦点顺序。

### 11.2 登录回归测试

- API ID/API Hash 校验与 `credentials_submitted` 参数保持不变。
- 保存凭据回填、API Hash 掩码、代理启停和代理密码掩码保持不变。
- 二维码、手机号、验证码、两步验证、取消和敏感字段清理测试继续通过。
- 账号状态页的安全重新登录流程不受影响。

### 11.3 视觉与打包测试

- 在 100% 和 125% 缩放、常见 1366×768 及以上可用区域检查展开和折叠状态。
- 不出现横向滚动、文字裁切、按钮遮挡或窗口超出可用屏幕。
- 冻结 EXE 能显示指南、调用系统浏览器边界并完成现有自检。
- 发布资产与日志秘密扫描不包含测试 API 值、手机号、确认码或其他真实凭据。

## 12. 验收标准

- 首次无凭据登录时，无需查阅 README 即可找到官方入口并理解完整申请流程。
- 打开官网后登录窗口与已填内容保持原状。
- 已有凭据时指南不阻碍快速登录，但始终可以重新展开。
- 浏览器或复制失败有可恢复的本地反馈，不影响原登录流程。
- 原登录、账号安全、加密存储和打包测试全部通过。
- 自动化与人工证据不读取、记录或发布真实 Telegram 凭据。

# 下载目录与命名模板设计

状态：按用户已确认的 P1 顺序实施。本文定义第 8 项，也是本组 P1 功能的最后一项。

## 目标

允许用户组合来源、年月、媒体类型、消息日期和消息 ID 来组织下载目录与文件名，同时维持项目内存储、Windows 文件名兼容、防目录穿越和重复文件安全。

## 配置模型

新增两个全局模板，保存在现有项目内 `settings.json`：

- 目录模板，默认 `{source}/{year_month}/{media_type}`；
- 文件名模板，默认 `{original_name}`。

旧设置文件缺少字段时自动使用默认值，生成路径与当前版本完全一致，不迁移或移动已有文件。

## 占位符

目录模板支持：

- `{source}`：Telegram 来源标题；
- `{year}`、`{month}`、`{year_month}`：消息日期的年、月和年月；
- `{media_type}`：`photo/video/audio/voice/document/archive`；
- `{message_date}`：`YYYY-MM-DD`；
- `{message_id}`：Telegram 消息 ID。

文件名模板额外支持：

- `{original_name}`：安全化后的原始文件名；
- `{stem}`：不含扩展名的原始文件名；
- `{extension}`：包含前导点的扩展名。

示例预设：

- 现有布局：`{source}/{year_month}/{media_type}` + `{original_name}`；
- 日期优先：`{year}/{month}/{source}/{media_type}` + `{stem}_{message_id}{extension}`；
- 消息归档：`{source}/{message_date}` + `{message_date}_{message_id}_{original_name}`。

## 安全规则

- 目录模板必须是相对模板，只使用 `/` 分层；禁止绝对路径、反斜杠、空层级、`.`、`..`、未知占位符、格式说明和属性访问。
- 最多 8 层目录；目录模板最多 500 字符，文件名模板最多 200 字符。
- 文件名模板不能包含路径分隔符，并必须包含 `{original_name}` 或 `{extension}`，避免静默丢失扩展名。
- 每个渲染后的目录段和文件名继续经过 Windows 非法字符、保留名、尾随点空格与长度清理。
- 最终相对路径最多 220 字符，并在拼接后再次解析验证必须位于固定的项目 `downloads` 根目录内。
- 模板无法产生可用路径时拒绝保存或预览，不自动回退到不透明路径。

## 生命周期

- 设置页增加“下载路径”标签页、两个可编辑预设框、占位符说明和实时示例。
- 保存前用固定示例验证；错误时不关闭设置窗口。
- 保存成功后立即配置当前 `TaskPlanner`；之后新预检/新任务使用新模板。
- 已经生成的任务继续使用数据库中持久化的目标路径，不因设置变化移动文件或改变断点续传目标。
- 新连接或重启构建 Planner 时直接使用已保存模板。

## 打开目录

“打开目录”不再假定首层一定是来源名，而是从任务媒体的实际目标路径计算安全公共目录。单媒体任务打开其真实父目录；跨来源/跨月份任务打开共同的项目内上级目录。无媒体时回退到 `downloads` 根目录。

## 不在本项范围

- 选择项目根目录之外的盘符或网络目录。
- 按账号、发送者、消息正文、搜索词或正则重命名。
- 自动迁移、合并、清理旧文件。
- 单任务覆盖全局模板。

## 验收

- 默认模板与当前路径逐字兼容。
- 所有占位符、三个预设、旧设置迁移和即时应用都有测试。
- `..`、绝对路径、分隔符注入、保留名、超长结果、未知字段均被拒绝或安全化。
- 普通链接、搜索、订阅、批量导入使用同一渲染器，目标始终位于项目根目录。
- 重启后模板继续生效，旧任务目标保持不变。

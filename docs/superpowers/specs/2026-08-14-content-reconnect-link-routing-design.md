# Telegram 账号内容重连与链接路由修复设计

日期：2026-08-14
状态：已确认设计，待实施计划

## 背景与问题结论

v0.3.1 已能解析并下载用户提供的消息链接 `https://t.me/Zhangzhoulao66/56156?single`，本地任务库中也存在该链接对应的两项已完成媒体。当前故障集中在账号内容页的连接恢复和界面状态：

- Telegram 短时网络失败后，账号内容页保持离线状态，群组列表、搜索框和搜索按钮没有可靠恢复。
- 进入账号内容页或选择群组时，没有统一的连接检查与有限重试流程。
- 群组同步只在启动、登录成功或手动刷新时触发；选择群组不会恢复该群上次搜索上下文。
- 离线状态直接禁止输入关键词，用户无法先填写条件再等待重连。
- 登录窗口未回填已保存的 API ID、API Hash 和代理设置，网络错误看起来像凭据丢失。
- 账号内容页的关键词框不识别 Telegram 消息链接，容易让用户把“扫描链接”和“群内关键词搜索”混为一体。

## 目标与验收标准

本次修复形成一个本地候选版本，满足以下行为：

1. 启动程序、进入账号内容页、选择群组和执行搜索时都会检查 Telegram 连接。
2. 瞬时网络失败按“立即、1 秒后、3 秒后”最多尝试三次；界面显示正在重连、恢复成功或重连失败，不删除仍有效的登录会话。
3. 进入账号内容页时，群组列表缓存超过 60 秒才自动同步；手动点击“刷新”始终强制同步。
4. 选择群组后恢复该群最近一次搜索的关键词、筛选条件和已有结果；不会自动执行全群历史扫描。
5. 离线时关键词框仍可编辑。点击搜索后先自动重连，成功则继续原搜索，失败则保留全部输入并给出可重试提示。
6. 关键词框检测到受支持的 `t.me` 消息、频道或群组链接后，自动切换到任务中心并执行“扫描预览”；不会自动加入下载队列。
7. 登录窗口显示已保存的 API ID，API Hash 以密码框遮罩方式回填，并恢复代理设置。网络失败不能再表现为凭据被清空。
8. 应用拥有的持久数据、缓存、日志、缩略图、下载文件、更新文件和测试/构建产物继续放在项目或应用目录中，不新增 AppData 等 C 盘持久写入。
9. 自动化测试、正式构建自检和 Windows 图形界面检查全部通过后，才交付便携包与安装包候选版。

## 非目标

- 不实现空关键词的全群历史浏览或无限滚动消息流。
- 不增加后台常驻轮询；仅在明确入口和用户动作时检查连接或刷新缓存。
- 不在识别链接后自动下载，避免误操作和大量流量消耗。
- 不更换 Telegram 客户端库、数据库格式或下载目录结构。
- 本次不自动推送远程仓库或发布正式版本；远程合并与发布需在候选版验证后由用户再次授权。

## 结构设计

### 1. 统一连接恢复器

控制器增加单一的“确保 Telegram 在线”入口，供启动、账号内容页激活、群组选择和搜索共用。它负责：

- 合并并发重连请求，防止多个界面动作同时创建连接。
- 区分瞬时网络错误、会话失效和凭据缺失。
- 对瞬时错误执行有上限的重试，并把连接状态发送给界面。
- 会话失效时沿用现有安全处理：仅清除无效会话，保留 API 和代理配置，再引导用户重新登录。
- 凭据缺失时直接打开已回填的登录页，不进行无意义重试。

连接过程在后台任务中执行，不冻结 Qt 主线程。关闭窗口、切换账号或重新提交操作时，可以取消不再需要的等待。

### 2. 群组列表同步与选择

账号内容服务记录最近一次成功同步时间。进入账号内容页时：

- 已在线且缓存年龄不超过 60 秒：立即显示缓存，不请求 Telegram。
- 缓存已过期或尚未同步：先显示缓存，再在连接恢复后同步。
- 离线：保留缓存和筛选功能，同时显示连接状态。

手动刷新忽略缓存年龄，连接成功后强制同步。同步失败不清空旧列表。

选择群组时，界面向控制器发送群组标识。控制器从本地搜索历史中加载该群最近一次会话并恢复关键词、日期、媒体类型和结果；若没有历史，仅显示空条件。选择动作会触发连接检查，但不会自动重新执行搜索。

### 3. 搜索与链接路由

搜索输入分为两条明确路径：

- 普通文本：作为当前群组的服务端关键词搜索。必须已选择群组且关键词非空。
- 受支持的 Telegram 链接：交给现有链接解析器规范化，切换到任务中心，填入来源链接并自动执行扫描预览。

链接扫描只产生预览和待确认项目。用户仍需在任务中心确认，才能加入下载队列。无法识别的链接保留在原输入框，并显示具体格式错误。

普通搜索在离线时仍允许编辑和提交。提交后保存当前表单快照，调用统一连接恢复器；恢复成功后继续搜索，恢复失败后还原表单并提供重试，不创建空历史记录。

### 4. 登录窗口回填

登录窗口增加显式的已保存设置加载接口，由控制器在展示窗口前调用：

- API ID 以数字回填。
- API Hash 从加密凭据库读取到内存并填入密码模式输入框，不写入日志或明文配置。
- 代理类型、地址、端口、用户名和密码按现有保存规则恢复。
- 用户可直接重试二维码登录，也可修改配置后保存。

二维码请求因网络失败时，窗口保留回填内容并显示“网络连接失败，可重试”；只有凭据格式错误才提示修改 API 信息。

### 5. 界面状态

账号内容页使用可区分的状态文案：

- `正在连接 Telegram…`
- `正在重连（1/3）…`
- `连接已恢复`
- `当前离线，可先输入关键词`
- `重连失败，请检查网络或代理后重试`
- `正在同步群组…` / `同步完成`

离线不禁用关键词、日期、媒体筛选或搜索按钮；点击搜索会进入重连流程。只有在连接、同步或搜索请求正在执行时才暂时防止重复提交，同时允许取消或切换页面。旧的群组列表和搜索结果始终保留到新结果成功返回。

## 数据流

1. 用户进入账号内容页。
2. 界面显示本地缓存，控制器检查连接和 60 秒缓存年龄。
3. 必要时控制器在后台重连并同步群组；成功后原位更新列表。
4. 用户选择群组，控制器恢复该群最近搜索会话。
5. 用户输入普通关键词并搜索：连接检查成功后调用内容搜索服务，结果写入本地历史并显示。
6. 用户输入 `t.me` 链接并搜索：链接解析器规范化，主窗口切换任务中心，扫描器生成预览，等待用户确认加入队列。

## 错误与隐私处理

- 瞬时网络错误只改变连接状态，不删除 API Hash、会话、缓存或搜索条件。
- `AuthKeyUnregisteredError` 等会话失效错误进入重新登录流程，不能无限重试旧会话。
- 所有后台异常转换为用户可理解的状态，同时把不含密钥的技术细节写入项目内日志。
- 日志不得记录 API Hash、会话串、代理密码或二维码令牌。
- 自动化测试使用模拟网关和临时项目目录，不读取或修改用户的真实 Telegram 会话和下载数据。

## 测试设计

实施必须先增加失败测试，再写生产代码。覆盖：

- 连接恢复器的成功、三次瞬时失败后停止、恢复成功、并发去重、取消和会话失效分支。
- 进入账号内容页的缓存新鲜/过期逻辑，以及手动强制刷新。
- 群组切换恢复各自最后一次搜索，不串用其他群组结果。
- 离线输入可编辑、提交后重连并继续搜索、失败后保留条件。
- `?single` 等链接规范化后路由到任务中心并自动扫描预览，但不加入下载队列。
- 登录窗口 API/代理回填、API Hash 遮罩和网络错误保留输入。
- 既有下载队列、暂停续传、文件命名、设置、更新检查和项目内路径测试不回归。

完成自动化测试后，用隔离的测试数据目录执行 Windows 图形界面自检。用户提供的链接用于只读扫描和队列流程核验；若本地已有完成记录，不重复下载同一媒体。最终分别验证便携包和安装包启动、数据路径、登录恢复、账号内容搜索、链接预览、下载控制和在线更新入口。

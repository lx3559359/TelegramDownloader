# TelegramDownloader 二维码完整显示设计

日期：2026-08-14

状态：用户确认

适用版本：v0.2.x

## 问题与证据

登录页当前把二维码按固定 `8px` 模块渲染，再把原始 `QPixmap` 直接放入只设置了 `232×232` 最小尺寸的 `QLabel`。使用接近真实 Telegram 长度的 token 在无界面 Qt 中复现得到：

- 登录框：`520×512`
- 二维码标签：`472×233`
- 二维码图片：`328×328`
- 完整可见：`false`

`QLabel` 不会自动缩放 pixmap，因此图片上下部分被标签裁切。截图中的顶部、底部白色静区和二维码模块缺失与该尺寸关系一致。

## 目标

- 二维码在常见 Windows DPI 和当前登录框宽度下完整显示。
- 保留四模块白色静区，避免影响 Telegram App 扫码。
- 每个二维码模块使用整数像素绘制，不进行插值缩放或非等比拉伸。
- 登录框在用户截图所示约 `871×711` 可用区域内保持可见。
- 不改变 QR token 生命周期、登录流程、凭据存储或项目本地数据路径。

## 非目标

- 不重新设计登录向导视觉风格。
- 不修改 Telegram QR 授权协议、刷新时序或 2FA 流程。
- 不处理与本缺陷无关的应用启动连接顺序。

## 方案

### 整数模块自适应渲染

`render_qr_image` 接受最大边长，登录页使用 `300px`。生成包含 `border=4` 静区的二维码矩阵后，按以下规则决定模块大小：

1. 用 `max_side // matrix_side` 计算可容纳的最大整数模块像素数。
2. 模块大小上限保持现有 `8px`，下限为 `1px`。
3. 最终边长为 `matrix_side × module_pixels`，保证不超过 `300px`。
4. 使用 `QPainter` 按整数坐标绘制黑色模块，背景保持纯白；不调用 `QPixmap.scaled`、`setScaledContents` 或平滑插值。

如果二维码矩阵本身已经大于最大边长，渲染器拒绝生成并返回安全错误，避免静默裁切。Telegram QR token 的正常长度不会触发该保护。

### 固定完整显示区域

登录页的 `qr_image` 使用 `300×300` 固定显示区域，水平居中加入布局。渲染结果小于 `300px` 时在标签中居中显示，周围保留界面背景；二维码自身的白色静区仍由图片提供。

固定区域在对话框创建时就参与尺寸计算，不依赖切换到 QR 页后 QLabel 是否刷新 size hint。`show_qr` 切换页面后请求一次布局尺寸调整，确保首次从凭据页进入 QR 页时窗口高度正确。

### 错误与安全

- URL 格式校验保持不变。
- 渲染失败只显示安全错误类型，不记录 QR URL 或 token。
- 二维码仍只存在于内存，不保存图片文件。
- 不读取、迁移或重写现有 `secrets.dat`、StringSession、任务数据库和下载目录。

## 测试设计

先添加会在当前实现上失败的回归测试：

1. 用真实长度 token 显示二维码并处理 Qt 布局事件，断言 pixmap 的宽高都不超过标签宽高。当前实现会因 `328 > 233` 失败。
2. 使用多种 token 长度，断言图片始终为正方形、边长不超过 `300px`，且模块边缘保持整数像素。
3. 检查图片四条边和黑色内容包围盒之间存在完整白色静区。
4. 验证二维码标签为 `300×300` 且图片居中，不启用自动拉伸。
5. 保留无磁盘写入、倒计时、刷新、切页清理和取消行为测试。

修复后运行二维码/UI 聚焦测试、完整测试套件和 Ruff。重新构建便携版，在与用户截图相近的窗口尺寸下启动 QR 页并截图，确认二维码四边、定位图形和白色静区全部可见。

## 验收标准

- 自动化尺寸复现从 `fully_visible=false` 变为 `true`。
- 完整二维码包含上下左右白色静区，没有裁切、拉伸或模糊插值。
- 登录框操作按钮、倒计时和状态文字仍完整可见。
- Telegram App 能扫描打包程序显示的二维码。
- 完整测试、Ruff、便携版自检和视觉烟测通过。
- 所有新增测试输出和临时文件继续位于项目路径。

# Telegram 账号内容浏览与选择性下载设计

日期：2026-08-14  
实现目标版本：0.3.0（正式发布仍需另行确认）

## 目标

在现有链接扫描下载之外，增加独立的“内容浏览”页面。用户登录 Telegram 后，程序自动识别当前账号已加入的群组和频道；用户先选择一个会话，再按关键词、日期和媒体类型搜索其中的可下载内容。搜索结果以可勾选列表展示，所选媒体复用现有任务队列、暂停恢复和断点续传能力。

群组缓存、搜索历史、结果摘要和缩略图必须全部保存在应用目录内，不向 C 盘写入项目数据。

## 已确认范围

- 只列出当前账号已加入的群组和频道，不列出私聊或机器人会话。
- 搜索前必须先选择一个群组或频道，不做跨全部会话的全局搜索。
- 搜索结果只展示带可下载媒体的匹配消息。
- 搜索记录、筛选条件和结果摘要持久保存，程序重启后仍可查看和继续选择。
- 每条媒体结果可独立勾选，并支持全选、反选；Telegram 相册可展开后逐项选择。
- 登录或启动后自动同步一次群组/频道列表，同时提供手动刷新。
- 采用独立“内容浏览”页面，不把浏览流程塞进现有链接输入卡片或弹窗。
- 搜索结果使用紧凑表格，包含缩略图或类型图标、日期、摘要、媒体类型和大小。

## 不在本轮范围

- 私聊、机器人会话和跨全部群组/频道的全局搜索。
- 消息发送、转发、删除、编辑、回复或群组管理。
- 保存完整聊天记录、全文本索引或离线全文搜索。
- 媒体播放、完整图片查看器和下载前的原文件预加载。
- 多 Telegram 账号同时在线；缓存按账号隔离，但界面仍只操作当前登录账号。
- 后台定时轮询群组列表；本轮只在启动/登录后自动同步，并允许手动刷新。

## 界面与交互

### 导航与页面结构

现有左侧导航增加“内容浏览”。主窗口中心区域改为可切换页面：

1. “任务中心”保持现有链接扫描、任务表格和实时概览。
2. “内容浏览”显示群组/频道列表与搜索结果；任务中心右侧实时概览在该页面隐藏，避免压缩搜索结果空间。

内容浏览页面由两列组成：

- 左列为群组和频道列表，提供按名称筛选、同步数量、上次同步时间和“刷新”按钮。
- 右列顶部为当前会话、关键词、日期范围、媒体类型、结果数量上限和“搜索/取消”按钮；中部在“搜索结果”和“搜索记录”之间切换；底部固定显示选择数量、已知总大小、全选、反选和“加入下载队列”。

### 群组与频道同步

- 页面先立即展示当前账号上次缓存的列表，再在登录恢复成功后进行一次后台同步。
- 同步包含当前账号已加入的普通群组、超级群组和频道，包括已归档会话；不包含私聊和机器人。使用稳定的 Telegram peer ID 作为标识，不以可变用户名作为主键。
- 当前账号仍加入的会话更新名称、用户名、类型和归档状态；已经退出或失权的会话标记为不可用，而不是立即删除其搜索历史。
- 手动刷新期间保留旧列表可见，避免界面清空闪烁。

### 搜索行为

- 关键词去除首尾空白后必须非空，避免意外扫描大型频道的全部历史。
- 搜索只针对当前选中的群组或频道，调用 Telegram 服务端消息搜索，并同时应用日期、媒体类型和数量限制。
- 结果数量上限默认 500，可设置为 1–10,000。首批最多返回 100 个媒体结果；存在更多内容且尚未达到上限时显示“加载更多”，后续每批最多 100 个。搜索会话保留 Telegram 分页所需的最后消息位置，但不承诺跨程序重启后从中断位置精确续搜；重启后可查看已有结果或执行“重新搜索”。
- 搜索结果按消息时间倒序显示。普通消息最多产生一个媒体结果；相册中任一消息命中时，补齐同一 `grouped_id` 的相册成员，按消息 ID 排序并在界面中可展开逐项选择。
- 每页搜索结果获取后立即显示并批量保存。用户取消、断网或限流中断时保留已获取结果，并将搜索会话标记为“不完整”；“重新搜索”会原位刷新同一组会话、关键词和筛选条件，不新增重复历史。

### 搜索记录与选择

- 搜索记录保存群组、关键词、日期、媒体类型、创建/更新时间、完成状态、结果数量和结果摘要。
- 相同账号、群组、规范化关键词和筛选条件对应一条可刷新的搜索记录。
- 用户选择状态随结果持久保存；程序重启后重新打开记录仍能看到上次勾选。原位重新搜索时，仍存在的相同媒体保留选择状态，新结果默认不选，已经消失的旧结果在搜索完成后移除。
- 可删除单条搜索记录或清空当前账号的搜索历史。删除历史会清理不再被其他记录引用的缩略图，但不删除下载任务、部分下载文件或已完成文件。
- 已加入现有任务库或已经下载的媒体显示状态并默认不可再次勾选；批量提交时再次做数据库级防重复检查，以处理界面展示后任务状态发生变化的情况。

## 架构与组件边界

### Telegram 网关

扩展 `TelegramGateway` 协议，但不把数据库或界面逻辑放入网关：

- `account_profile()` 返回稳定账号 ID 与显示名称，用于缓存隔离。
- `iter_content_dialogs()` 返回当前账号加入的群组和频道摘要。
- `search_media_page(peer_ref, query, cursor)` 返回最多 100 项的 `RemoteSearchPage`，其中包含媒体结果、下一页游标和是否已到末尾；网关负责把 Telethon 分页细节封装在内部。
- `expand_album(peer_ref, message_id, grouped_id)` 补齐相册成员。
- `load_thumbnail(peer_ref, message_id, media_id)` 按需返回受大小限制的小缩略图；没有缩略图时返回空值。
- 继续复用现有异常映射，将无权访问、临时网络错误、限流等待和媒体引用过期转换为项目内异常类型。

网关返回纯领域对象，不暴露 Telethon 实体给上层。

### 内容浏览服务

新增 `ContentBrowserService`，负责：

- 读取当前账号资料并驱动群组/频道同步。
- 规范化关键词和筛选条件，创建或刷新搜索会话。
- 逐页接收媒体结果、相册去重、批量持久保存和发布界面快照。
- 管理搜索取消、加载更多、历史删除、选择状态和不可用结果。
- 将用户选择转换为现有 `TaskPlanner` 能处理的远程媒体集合。

服务不直接下载媒体，也不拥有下载任务生命周期。

### 内容目录仓库

新增独立 `CatalogRepository`，数据库路径为 `data/database/catalog.sqlite3`。搜索数据与 `tasks.sqlite3` 分离，以便用户清理搜索历史而不影响下载恢复数据。

建议表结构：

- `accounts`：`account_id`、显示名称、最后使用时间。
- `dialogs`：`account_id`、`peer_ref`、标题、用户名、会话类型、归档状态、可用状态、最后同步时间。
- `search_sessions`：搜索 ID、账号、会话、规范化关键词、筛选条件、状态、分页信息、结果数量、创建/更新时间和安全错误摘要。
- `search_results`：结果 ID、搜索 ID、`peer_ref`、`message_id`、`grouped_id`、`media_id`、媒体类型、文件名、大小、消息时间、有限长度摘要、缩略图键、选择状态和可用状态。

约束与索引：

- 所有账号相关表都包含 `account_id`，查询必须显式限定当前账号。
- `dialogs` 对 `(account_id, peer_ref)` 唯一。
- `search_results` 对 `(search_id, peer_ref, message_id, media_id)` 唯一。
- 搜索会话按 `(account_id, peer_ref, normalized_query, filters_fingerprint)` 唯一，以支持原位刷新。
- 数据库使用版本化迁移；创建或迁移失败时不修改现有 `tasks.sqlite3`。

### 缩略图缓存

- 缩略图保存在 `data/cache/thumbnails/`，仅当结果行进入可见区域时按需加载。
- 缩略图失败不影响结果展示，界面退回媒体类型图标。
- 缓存键包含账号 ID、peer ID、消息 ID 和媒体 ID，避免账号串图。
- 单个缩略图最大 256 KiB，缓存总量上限 512 MiB；超过上限时按最近最少使用顺序清理，仅删除缩略图，不删除搜索结果元数据。
- 设置页增加“清理缩略图缓存”，不清理搜索元数据或下载文件。
- 缓存必须通过现有路径约束验证，任何解析后逃出应用目录的路径都被拒绝。

### 任务计划与下载队列复用

扩展 `TaskPlanner`，增加从已选 `RemoteMedia` 构建预览的入口，继续复用现有：

- 文件名清理和按来源标题、年月、媒体类型归档。
- 目标路径冲突消解。
- 已知大小汇总和未知大小计数。
- `TaskRecord`、`MediaItem`、任务仓库、调度器、下载器和断点续传。

提交前弹出与链接扫描一致的确认摘要。任务标题使用“群组标题（搜索：关键词）”。只有最终勾选且数据库防重复后仍有效的媒体进入任务；全部被跳过时不创建空任务。

## 数据流

1. 登录恢复完成后，控制器取得 `AccountProfile`，加载该账号缓存并触发一次后台会话同步。
2. 用户选择会话并提交搜索；控制器把界面值转换为 `ContentSearchQuery`。
3. `ContentBrowserService` 创建或刷新搜索会话，调用网关并把每页结果批量写入 `CatalogRepository`。
4. 控制器以节流方式更新结果模型；缩略图加载器只请求当前可见行。
5. 用户勾选结果并确认；服务重新校验可用性与重复状态，交给 `TaskPlanner` 生成预览。
6. 用户确认后写入现有任务仓库并启动调度器；内容页面更新结果的“已入队”状态，任务中心显示新任务。

## 并发与生命周期

- 同一时间只允许一个账号级会话同步和一个活动搜索；新搜索前必须取消或等待当前搜索结束。
- 界面关闭或切换账号时取消活动同步、搜索和缩略图任务，等待协程收尾后再断开 Telegram。
- 切换内容页面不会取消已提交的下载任务；下载队列生命周期仍由调度器拥有。
- 搜索结果写入使用短事务和批量提交，避免长时间锁住数据库。
- 群组缓存先读后刷新；离线启动时仍可查看历史，但搜索和加入需要重新取媒体引用的项目会给出联网提示。

## 错误处理

- 未登录：显示登录引导，不调用同步或搜索接口。
- 同步失败：保留缓存列表和上次同步时间，状态栏显示安全错误；手动刷新可重试。
- Telegram 限流：显示剩余等待秒数并暂时禁用同步/搜索，等待结束后允许用户重试，不做高频自动重试。
- 搜索取消或临时网络中断：保留部分结果，搜索会话标记为“不完整”。
- 会话失权或退出：群组标记不可用，历史仍可查看，不能继续搜索或把失效结果加入队列。
- 消息删除或媒体引用过期：对应结果标记不可用；其余选择继续提交。媒体引用在真正下载时仍沿用现有刷新和错误处理规则。
- 重复媒体：提交时跳过，并报告已选择数、已入队数、重复数和不可用数。
- 数据库或缓存损坏：搜索目录功能进入只读错误状态，不影响 `tasks.sqlite3` 中已有下载任务运行。
- 所有日志继续经过脱敏过滤，不记录 API Hash、会话字符串、电话号码、二维码令牌、代理密码或消息全文。

## 本地存储与隐私

- `catalog.sqlite3`、缩略图、日志、临时分页状态和测试产物全部解析到应用目录下。
- 不保存完整聊天历史；消息摘要在写入前去除不可显示字符并限制到 500 个 Unicode 字符。
- 搜索关键词属于本地隐私数据，不写入普通运行日志。
- 账号 ID 只用于本地隔离，不上传到 GitHub、魔塔或更新服务。
- 便携包和安装包不包含真实数据库、搜索历史、缩略图、下载文件或登录会话。
- 安装升级和普通卸载继续保留应用目录内用户数据；用户主动“清空搜索历史”只影响当前账号的目录数据。

## 测试与验收

实施采用测试驱动方式，至少覆盖：

1. 网关：账号资料、仅群组/频道过滤、稳定 peer ID、服务端关键词搜索、日期/媒体过滤、100 项分页、相册补齐和异常映射。
2. 仓库：首次建库、版本迁移、账号隔离、会话同步、同条件原位刷新、分页结果去重、选择持久化、历史删除和损坏隔离。
3. 服务：缓存先显示后同步、同步并发锁、搜索取消、部分结果状态、加载更多、缩略图失败回退和切换账号取消后台任务。
4. 任务集成：仅提交勾选项、相册逐项选择、全重复不建任务、部分重复报告、任务标题与归档路径正确。
5. 界面：导航切页、未登录引导、群组名称筛选、搜索/取消状态、结果与历史切换、全选/反选、选择统计和重启后恢复。
6. 回归：现有链接扫描、Telegram 登录、任务暂停恢复、断点续传、实时速度、更新签名和全部原有测试继续通过。
7. 打包：直接启动目录、便携 ZIP 和安装包自检通过；安装、原位升级和卸载验证搜索目录数据保留；所有可写路径仍在应用目录。

验收场景：使用已登录账号启动程序，自动看到已加入群组和频道；选择一个会话搜索关键词，逐条看到带媒体的结果；勾选任意若干项加入队列并完成下载；重启程序后搜索历史、结果摘要和未提交选择仍存在，现有下载任务与文件不受影响。

## 发布边界

规格确认后先形成实施计划，再在隔离工作树中开发和测试。完成实现与打包验证不等于自动发布；合并、版本号、GitHub Release、魔塔同步和在线更新指针切换仍需用户另行明确确认。

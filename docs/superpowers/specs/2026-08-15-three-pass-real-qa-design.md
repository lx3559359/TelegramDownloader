# TelegramDownloader v0.4.2 三轮真实化自检设计

## 目标

在同一项目内运行目录上连续执行三轮递进式全链路检查。每轮都必须覆盖会话启动、群组同步、搜索与预览、选择入队、真实下载、暂停续传、异常恢复、安装验证和在线更新；任何缺陷都先形成稳定复现与失败测试，再进行最小修复和完整回归。

## 安全边界

- 只使用 `D:\Codex Project\Telegram下载器\.worktrees\content-ux` 下的源码、构建目录、运行数据和测试临时目录。
- 复用项目运行目录中已有的 DPAPI 加密凭据与 Telegram 会话，不输出 API ID、API Hash、手机号、会话令牌、群名、关键词或消息正文。
- 真实下载只增加验证所需的最小字节量；不删除现有任务、下载文件、账号会话或日志。
- 受控崩溃只终止专用探针进程，不强制结束用户正在使用的其他程序。
- 不推送 GitHub 或魔塔，不创建标签或 Release，不提升签名在线更新清单。

## 三轮测试结构

### 第一轮：正常使用路径

1. 从已保存会话启动，确认无需二维码并可恢复本地群组与搜索历史。
2. 刷新真实群组列表，记录开始反馈、进度反馈、完成数量和耗时。
3. 执行真实关键词搜索，验证输入、进度、结果、缩略图和双击预览。
4. 选择可用且未入队的结果加入队列；若当前结果全已入队，验证排除计数和禁用状态，并用隔离夹具覆盖新增入队路径。
5. 继续真实媒体任务，观察字节增长，然后暂停并再次继续，确认断点未倒退。
6. 在正常关闭后确认任务落盘、Telegram 网关断开且无残留异步任务。
7. 检查 GitHub/魔塔双源签名清单以及当前版本的无更新或可更新判定。
8. 对便携包、安装包执行现有烟雾测试，并确认账号数据没有进入发布包。

### 第二轮：异常与重复交互路径

1. 重复启动应用，确认单实例提示不会创建第二个主窗口。
2. 在群组刷新、搜索和加入队列期间验证重复点击合并或禁用，并确认按钮最终恢复。
3. 取消搜索后立即发起新搜索，确认旧任务停止、新任务可输入且进度重新开始。
4. 让真实下载产生新字节后运行专用崩溃探针；重启确认下载中状态恢复为可调度状态、字节保留并可继续。
5. 在恢复下载后立即暂停并关闭，确认宽限期内完成连接归还，无 `Connection._send_loop`、`Connection._recv_loop` 或未等待协程警告。
6. 模拟一个更新源不可用、两个源版本不一致、旧签名版本和最低更新器版本不兼容，确认各自采用正确的降级或阻断策略。
7. 重复执行安装、覆盖升级和卸载数据保留烟雾测试。

### 第三轮：交付候选路径

1. 从干净应用进程状态再次执行完整真人式启动、刷新、搜索、预览、入队、下载、暂停、继续和退出流程。
2. 运行全部自动化测试、Ruff、打包自检和安装器自检。
3. 对构建前后运行数据做文件数、总字节数和聚合哈希比对；允许自检报告按设计更新，但不得丢失账号会话、任务数据库或下载文件。
4. 检查 EXE 可直接启动和正常关闭，记录新日志中的错误数量并确认没有残留进程。
5. 重新计算 EXE、便携 ZIP、安装包的大小和 SHA-256；检查 ZIP 不包含 `data/` 或 `downloads/`。
6. 对照本设计逐项审计证据，更新验证记录并本地快进合并至 `main`。

## 缺陷处理

每个异常按固定顺序处理：保留原始错误和时间点；重复操作以确认可复现；从界面、控制器、服务、网关或打包边界向后追踪根因；写一个只覆盖该行为的失败测试并确认正确失败；实施最小修复；运行焦点测试、相关测试和全量测试；提交修复后从当前轮的失败步骤重新开始。未稳定复现的问题只增加诊断证据，不凭猜测修改生产代码。

## 成功标准

- 三轮均有独立的逐项结果，不用前一轮结果代替后一轮。
- 已保存会话三次启动均无需二维码，群组刷新和搜索均有可见反馈且不会永久卡住。
- 搜索预览、选择入队、真实字节增长、暂停续传和崩溃恢复都有运行时证据。
- 便携包、安装包、覆盖升级、卸载保留、双源在线更新和项目内数据隔离均通过。
- 所有新增或修改行为遵循测试先失败、代码后修复的顺序，最终完整测试与 Ruff 通过。
- `main` 仅在所有证据齐全后本地快进，不进行任何外部发布。

# Telegram 会话稳定性与内容交互优化设计

## 背景与目标

当前版本已经能够保存 Telegram StringSession、同步账号群组、搜索媒体并加载缩略图，但用户仍会遇到重复扫码、断线后缺少明确状态、同步与搜索看起来没有开始、预览图过小以及整体交互等待感明显的问题。

本轮改进目标如下：

1. 普通断网不再触发二维码登录，只有 Telegram 明确判定授权失效时才重新登录。
2. 搜索结果采用更大的缩略图，并支持双击打开程序内预览。
3. 搜索开始后立即显示动态进度与实时扫描计数。
4. 缩短群组切换、同步、搜索、专辑展开与缩略图加载的体感等待时间。
5. 点击群组刷新后立即显示进行中、完成或失败反馈。

## 已确认方案

采用稳健型增量优化方案：保留现有表格与本地目录架构，增加 Windows 单实例保护、会话状态机、后台连接恢复、缓存优先显示、进度事件、实体缓存和有限并发。不会采用仅增加视觉反馈但不解决根因的方案，也不会采用容易触发 Telegram 限流的高并发方案。

## 会话与连接架构

### 单实例保护

Windows 启动入口增加当前用户范围的单实例保护。第二个 TelegramDownloader 进程启动时不创建 TelegramClient，而是提示“程序已在运行”并退出。这样可以避免安装版、便携版或重复启动的程序同时使用同一授权密钥，降低 `AuthKeyDuplicatedError` 导致会话失效的风险。

单实例状态不依赖 C 盘文件；Windows 使用当前用户范围的命名同步对象，测试环境使用可注入的保护接口。

### 会话保留规则

现有 StringSession 继续使用 Windows DPAPI 加密，保存于运行根目录下的 `data/config/secrets.dat`。

- `TransientNetworkError`、连接超时、代理暂时不可用和普通断开不会删除 Session，也不会打开登录窗口。
- `AuthKeyInvalidError`、`AuthKeyUnregisteredError`、`SessionRevokedError` 等 Telegram 明确授权错误才进入会话失效流程。
- 会话失效流程停止后台连接任务、清除已失效 Session、保留本地群组与搜索历史，并显示二维码登录。
- 日志只记录状态、错误类型和重试次数，不记录 Session、API Hash、代理密码或二维码令牌。

### 连接恢复

控制器维护一个连接监测任务和统一连接状态：`connected`、`reconnecting`、`offline`、`session_expired`。

- 应用启动时优先加载缓存界面，再验证已保存会话。
- 普通断线先立即重连，再等待 1 秒和 3 秒重试；三次均失败后进入离线状态，并由后台每 30 秒重试一次。同一时刻只允许一个重连任务。
- 搜索、同步或下载开始前可以唤醒同一个重连任务，不创建重复连接。
- 自动重连耗尽后保持离线，并显示“离线，点击重试”；用户操作可立即重新尝试。
- 网络恢复后状态自动返回“已连接”，不要求扫码。

## 内容同步与搜索数据流

### 群组同步

打开账号内容页时，先从 SQLite 目录缓存立即显示群组和频道，再在缓存过期时后台同步。

手动刷新始终触发一次同步，但连续点击不会叠加任务。同步过程保留旧列表，并通过进度回调报告已发现的群组数量。服务在完整同步成功后原子替换本地目录；失败或取消时继续使用上一次成功结果。

同步状态依次为：

- `正在连接 Telegram…`
- `正在刷新，已发现 N 个群组/频道`
- `刚刚同步，共 N 个`
- `刷新失败，已保留上次 N 个结果`

### 搜索进度

搜索请求发出后立即进入忙碌状态并显示不定进度条。Telegram 不提供可靠的服务端搜索总条数，因此不显示虚假的百分比；进度文本报告真实数据：已扫描消息数、已匹配媒体数和当前阶段。

进度事件每扫描 10 条消息时尝试更新，但两次界面更新至少间隔 200 毫秒；搜索结束时无条件发送最终状态。这样可避免每条 Telegram 消息都触发 Qt 重绘。搜索完成、取消、断网、会话失效或异常退出时必须在 `finally` 路径关闭进度状态。

新搜索会安全取消当前搜索，再使用最新表单快照开始。取消不会删除已有搜索历史或已经持久化的结果。

### 性能优化

- TelegramGateway 缓存已解析的群组实体，搜索、专辑展开、缩略图和预览共享缓存。
- 实体缓存绑定到当前 Gateway 生命周期；更换账号或 Gateway 后自然失效。
- 同一搜索页的专辑展开使用最多 4 个并发请求，并保留稳定排序。
- 可见缩略图加载使用最多 4 个并发请求；滚出视口的结果不会新增请求。
- 重复的群组同步、搜索和缩略图请求通过现有任务表及锁合并或拒绝。
- 本地缓存、搜索历史和结果先显示，网络操作始终在 qasync 后台任务中运行。

## 界面设计

### 连接与刷新反馈

账号内容页顶部显示连接状态：“已连接”“正在重连（N/M）”“离线，点击重试”或“登录已失效”。离线状态提供显式重试动作。

群组面板刷新按钮在同步时变为“刷新中…”，同时禁用重复点击。按钮下方显示小型不定进度条和同步计数；完成或失败后进度条隐藏，文本保留最终结果。

### 搜索反馈

搜索表单下方增加搜索状态区：不定进度条、阶段文本和取消按钮。点击搜索后该区域立即出现，不等待第一个 Telegram 响应。搜索结果和历史记录在搜索期间仍可查看。

### 大缩略图表格

保留结果表格及批量勾选流程。预览列目标尺寸约为 `112×84`，行高约为 `96`；具体数值可随 Windows 缩放比例调整。日期、摘要、类型、大小和状态列保持可见。

仅请求当前视口中的缩略图。无缩略图或不支持预览的媒体显示清晰的类型占位图标。

### 双击预览

双击结果行或预览单元格打开程序内模态预览窗口：

- 图片按可用窗口等比例缩放，可切换适应窗口和原始尺寸。
- 视频显示可获取的最大封面，不在本轮加入播放器。
- 文档、音频、语音和压缩包显示类型图标、原文件名、大小、日期和摘要。
- 预览缺失时按需复用缩略图加载管线；加载期间显示状态，失败只影响当前预览窗口。
- 所有预览缓存继续写入运行根目录下的 `data/cache/thumbnails`，不会写入系统临时目录。

## 异常处理

- 同步失败：停止动画，保留缓存列表，显示安全错误摘要。
- 搜索失败：停止进度，保留已保存历史和结果，允许重试。
- 搜索取消：标记当前搜索为不完整并恢复界面操作。
- Telegram 限流：显示等待时间，不进行无界重试。
- 缩略图或预览失败：显示占位图和局部错误，不影响下载队列。
- 会话失效：仅在授权错误证据明确时清除 Session 并进入登录流程。
- 应用重复启动：第二个进程在创建 Gateway 前退出，不接触会话文件。

## 数据与安全约束

设置、加密凭据、数据库、日志、缓存、下载、更新文件和临时文件继续位于应用或安装目录下。新增功能不得使用 `%APPDATA%`、`%LOCALAPPDATA%` 或系统 `%TEMP%` 保存项目数据。

单实例标识、日志和进度事件不得包含 Telegram Session、API Hash、代理密码、二维码令牌或消息正文全文。

## 验收标准

自动化测试至少覆盖：

- 第二实例不会创建 TelegramClient。
- 普通断网和重连失败不会删除 Session 或弹出二维码。
- 明确授权错误会清除 Session 并进入登录流程。
- 自动与手动重连共用单个任务。
- 群组刷新立即进入忙碌状态、报告计数并防止重复同步。
- 同步失败保留原列表。
- 搜索立即显示进度，报告扫描和匹配计数，并在所有退出路径停止。
- 实体缓存减少重复解析，专辑展开和缩略图并发不超过 4。
- 结果表格使用更大的图标尺寸和行高。
- 双击结果打开对应预览，失败不影响主页面。
- 所有新增路径仍受运行根目录守卫约束。

最终验收包括完整 pytest、Ruff、便携包冒烟测试、安装包构建，以及 Windows 图形界面对登录恢复、刷新反馈、搜索进度和双击预览的人工冒烟检查。

## 本轮不包含

- 视频直接播放。
- 全局跨群组搜索。
- 绕过 Telegram 限流或无限并发。
- 将运行数据迁移到系统用户目录或云端。

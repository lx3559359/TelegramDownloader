# TelegramDownloader

## 正式版下载

Windows 10/11 x64 正式版请从以下稳定发布入口获取：

- [GitHub 最新 Release（安装包与便携包）](https://github.com/lx3559359/TelegramDownloader/releases/latest)
- [魔搭镜像仓库](https://modelscope.cn/models/lx3559359/TelegramDownloader)
- 安装包会拒绝安装到 C 盘；便携包请解压到 D、E 等非 C 盘目录后运行。
- Windows 可能因未购买商业 Authenticode 证书显示 SmartScreen“未知发布者”；在线更新仍会强制验证 Ed25519 签名和 SHA-256。

一个面向 Windows 10/11 x64 的简体中文图形化 Telegram 下载器。它支持单条消息、相册、全账号关键词搜索，以及按日期、媒体类型和数量上限扫描频道/群组；下载任务可以暂停、断网续传并在程序重启后恢复。

项目同时交付绿色便携包和安装包，并使用 GitHub、魔搭双源的签名在线更新。所有由应用管理的配置、会话、数据库、日志、缓存、临时文件、更新备份和下载内容都位于应用目录，不把这些数据持久写入 C 盘。

## 主要功能

- 启动阶段立即显示加载状态，主窗口优先出现，账号与任务恢复在窗口显示后继续执行。
- 单条 `t.me` 消息链接下载，自动扩展同一相册。
- “账号内容”默认选择“全部会话”，可在当前账号可访问的群组、频道、私聊、机器人、收藏夹和已归档会话中执行 Telegram 服务端关键词搜索。
- 全账号搜索按一个总结果上限分页并显示每条结果的真实来源；也可选择单个群组或频道进行原有范围搜索。
- 搜索结果支持点击整个选择单元格或按空格键勾选，也可全选/反选并选择性加入下载队列；已存在任务会自动跳过并报告。
- 账号内容页使用浅灰蓝画布与白色立体卡片；筛选区和结果列采用稳定宽度，长摘要只在自身列内省略并可悬停查看全文。
- 普通链接、搜索和订阅统一去重；预览前与数据库提交时都会按 Telegram 媒体身份再次检查。
- 搜索记录和勾选状态可在重启后恢复；离线时仍可查看缓存记录，但同步、搜索和加入队列需要重新联网。
- 为已加入的群组或频道创建自动订阅；支持多个包含词、AND/OR、排除词、历史补抓范围、媒体类型和检查间隔。
- 后台订阅发现账号授权失效时会立即进入统一的重新登录流程；“连接正常”同时验证网络与账号授权。
- 首次配置个人 API ID/API Hash 后，默认使用 Telegram App 扫二维码登录；保留手机号验证码备用入口。
- 频道/群组按包含式日期范围、图片、视频、音频、语音、文档、压缩包和数量上限扫描。
- 支持粘贴多条 Telegram 链接或拖入 TXT 文件，统一预检无效项与重复项后一次加入队列。
- 专业三栏任务工作台，显示状态、进度、大小、速度、剩余时间和持久错误原因。
- 所有来源进入同一下载队列，多个任务共享 1–5 个全局媒体槽；等待任务显示“等待中 · 第 N 位”，可对选中项执行“优先下载”。
- 设置页支持实时调整 1–5 个全局媒体槽与总下载限速，修改后无需重启当前下载。
- 设置页支持安全的下载目录与文件名模板，可组合来源、日期、媒体类型和消息 ID，并实时预览新任务路径。
- 支持关闭到托盘、隐私安全的系统通知、可选开机启动，以及按星期和时间限制下载时段。
- 下载完成自动建立 SHA-256 完整性基线；支持按任务或媒体校验，并只重新下载异常文件。
- “健康诊断”可按需检查项目路径、磁盘空间、运行组件、数据库、登录凭据、Telegram 连接及 GitHub/魔搭签名更新源，并导出严格脱敏的诊断包。
- `.part` 分块文件按实际字节偏移续传；异常分片会留档，不静默覆盖已有文件。
- SOCKS5 与 HTTP 代理，可在保存前测试连接。
- 启动检查 GitHub / 魔搭正式版更新；Ed25519 验证清单，SHA-256 验证安装包与便携包，替换失败自动回滚。
- 敏感信息通过当前 Windows 用户的 DPAPI 加密，日志自动屏蔽已登记凭据和完整手机号。

## 后台运行、通知与下载时段

- 默认启用“关闭到托盘”。点击主窗口关闭按钮只隐藏窗口，下载和自动订阅继续运行；托盘菜单中的“彻底退出”才会安全停止调度器、连接和未完成任务。双击托盘图标可恢复同一个进程，重复启动程序也会激活已经运行的主窗口，不会创建第二套任务状态。
- 下载完成、部分失败、磁盘空间不足、订阅命中、登录失效、下载时段切换和发现正式版更新可显示系统通知。通知只使用固定的聚合文案，不包含账号、来源、消息、搜索词、文件名或路径；关闭通知不会改变下载和订阅结果。系统托盘或通知不可用时，程序会安全回退：后台启动改为显示主窗口，通知失败不会中断业务。
- “登录 Windows 后自动在后台启动”默认关闭，只能由用户明确开启。正式打包程序仅管理当前用户 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下名为 `TelegramDownloader` 的一个值，关闭设置即可删除；源码开发模式不写启动项，也不需要管理员权限。
- 下载时段可选择周一到周日，并支持同日、全天以及跨午夜窗口。时段结束时，正在下载的任务以“时段暂停”原因安全暂停；时段开始后只恢复这类任务，用户手动暂停的任务不会自动恢复。
- 自动订阅在主程序驻留托盘时继续检查。即使当前位于下载时段之外，订阅仍可发现并加入任务；任务会等待下一个允许下载的窗口。
- 后台模式不是 Windows 服务：只有当前用户已登录且程序正在运行时才执行，用户注销或 Windows 关机时会走正常退出流程；注销后不会继续下载或检查订阅。

## 便携版使用

1. 下载 `TelegramDownloader-<版本>-win-x64-portable.zip`。
2. 解压到 D、E 等非 C 盘目录。
3. 双击 `TelegramDownloader.exe`，无需安装 Python，也不要求管理员权限。
4. 不要只复制 EXE；它需要同目录的 `_internal` 运行时文件。

首次启动会在 EXE 同级创建：

```text
TelegramDownloader/
├─ TelegramDownloader.exe
├─ _internal/
├─ data/
│  ├─ config/settings.json
│  ├─ config/secrets.dat
│  ├─ database/tasks.sqlite3
│  ├─ database/catalog.sqlite3
│  ├─ logs/app.log
│  ├─ cache/thumbnails/
│  ├─ temp/
│  └─ update/
└─ downloads/
   └─ <频道名>/<YYYY-MM>/<媒体类型>/<文件>
```

## 安装版使用

安装程序会阻止把应用安装到 C 盘，并要求选择其他固定磁盘。应用数据跟随安装目录。普通卸载默认保留 `data` 与 `downloads`；只有明确选择删除本地数据时才会移除。Windows 自己维护的快捷方式和卸载记录不属于应用业务数据。

未购买 Authenticode 商业证书，因此 Windows SmartScreen 可能显示“未知发布者”。这不影响应用内部的 Ed25519 更新签名与 SHA-256 完整性校验。

## Telegram 登录

第三方 Telegram 客户端必须使用用户自己的 API ID 和 API Hash：

1. 在浏览器打开 [my.telegram.org](https://my.telegram.org)。
2. 使用手机号登录，进入 **API development tools**。
3. 创建应用并复制 API ID、API Hash。
4. 首次在本程序填写 API 凭据，点击“保存并生成二维码”。
5. 打开 Telegram App，进入 **设置 → 设备 → 连接桌面设备**，扫描程序显示的二维码并在手机端确认。
6. 如果账号启用了两步验证，再输入 Telegram 云密码。二维码过期会自动刷新，也可以手动刷新。

以后有效会话会自动恢复；前台操作或后台订阅发现会话失效时都会立即进入同一重新登录流程并显示新二维码。“连接正常”只有在网络可用且账号授权有效时才会显示。诊断记录只保留固定的脱敏授权原因类型，不保存 Telegram 返回的原始错误文本。二维码页始终可以切换到“改用手机号登录”，继续使用手机号、验证码和可选两步验证流程。

API Hash、代理密码和 Telethon StringSession 会写入 `data/config/secrets.dat`，但内容由 DPAPI 加密。把整个便携目录复制到另一台电脑或另一个 Windows 用户后，密文通常无法解密，需要重新登录。

## 下载流程

### 管理下载任务

任务中心支持按任务名称搜索，并可切换“全部、进行中、已暂停、部分失败、已完成、已归档”六种状态筛选；筛选项会显示当前匹配数量。任务表支持多选，可批量暂停、继续、重试失败任务或“校验文件”。选择一个任务后，下方详情区会列出每个媒体文件的类型、状态、完整性、进度、大小、重试次数和安全错误；双击已完成且未标记异常的媒体可以直接打开本地文件。

“归档所选”只整理已经完成的任务，不会删除媒体文件。归档可以随时恢复，下载文件和去重记录都会保留，因此同一 Telegram 媒体不会因为整理任务列表而被重复加入队列。文件打开前会重新读取数据库记录并校验路径必须位于应用目录；文件缺失或路径越界时只显示安全提示，不会修改任务状态。

任务摘要使用一次 SQLite 聚合查询刷新，不再为列表中的每个任务分别打开数据库查询；只有单选任务时才读取该任务的媒体明细。快照读取在后台线程执行，进度或状态变化会增量更新现有行，避免重置整个列表。任务数量增长后，搜索、状态切换和实时进度刷新仍保持本地响应。

普通链接、批量导入、账号内容搜索和自动订阅创建的任务统一进入同一调度器。调度器最多同时激活与全局媒体槽数相同的任务，并在任务之间轮转新释放的媒体槽；因此大量单文件任务不必等一个大任务全部完成。超过活动上限的任务显示“等待中 · 第 N 位”。选中等待任务后可点击“优先下载”，它会优先进入下一空出的活动位置；正在传输的媒体不会被强制中断。优先顺序保存在任务数据库中，程序重启后继续生效。

设置中的“全局媒体槽”控制全部活动任务合计同时下载的媒体数，可在 1–5 之间调整；只有一个任务时可使用全部槽，多个任务同时存在时按任务轮转等待媒体。“总下载限速”同样由所有任务和媒体共享，而不是每个文件各自获得一份带宽。两项设置保存后立即作用于当前运行的调度器；不限速只取消应用自身的速率限制，不会改变 Telegram、网络或磁盘的实际上限。下载分片会在后台批量写盘，暂停、取消和完成时仍执行持久化提交，进度只统计已经确认写入的字节。等待队列、媒体槽和限速设置都保存在应用目录，继续遵守不把业务数据写入 C 盘的边界。

### 自定义下载路径和文件名

设置页的“下载路径”标签可分别编辑目录模板和文件名模板，并用示例媒体实时预览结果。目录可使用 `{source}`、`{year}`、`{month}`、`{year_month}`、`{media_type}`、`{message_date}`、`{message_id}`；文件名还可使用 `{original_name}`、`{stem}`、`{extension}`。默认仍为 `{source}/{year_month}/{media_type}/{original_name}`。

模板只能生成 `downloads` 内的安全相对路径，绝对路径、父目录跳转、未知占位符、Windows 非法名称和过长路径会在保存前被拒绝。设置保存后立即作用于新预览；已经加入队列的任务继续使用数据库中保存的原路径，不会被改名或迁移。任务的“打开目录”按该任务实际保存的媒体路径打开；跨多个来源时打开它们的共同下载目录。

### 文件完整性校验与精准修复

新下载完成时会自动计算并在 `data/database/tasks.sqlite3` 内保存 SHA-256 完整性基线和 UTC 校验时间；哈希不会上传到 Telegram、GitHub 或魔搭。由旧版本迁移的完成文件显示“未校验”，首次手动校验会建立基线。程序不会在启动时扫描全部下载文件，避免大目录拖慢启动。

在任务详情中多选媒体后可点击“校验所选”；结果会区分已校验、文件缺失、大小异常、哈希异常和无法读取，并显示进度与取消按钮。对异常项点击“重新下载所选”时，现有最终文件和 `.part` 分片会先在原目录保留为 `.corrupt`、`.corrupt.2` 等冲突安全留档，然后只重新下载所选异常媒体，不会顺带重试同任务的其他失败项。

校验会读取完整文件，耗时取决于文件大小和磁盘速度。`.corrupt*` 留档不会被程序自动删除；确认新文件可用后可由用户自行清理。所有哈希、进度、分片、留档和修复状态继续位于应用目录，不写入 C 盘业务目录。

### 浏览账号内容并选择下载

打开左侧“账号内容”后，搜索范围默认是“全部会话”。输入必填关键词，设置日期、媒体类型和 1–10,000 的账号级总结果上限，即可搜索当前账号可访问的群组、频道、私聊、机器人、收藏夹和已归档云端会话；也可以改选一个群组或频道，仅搜索该会话。直接命中的媒体会先渐进显示，相册补齐和缩略图加载随后进行；结果稳定前不会开放加入下载队列。程序会自动补齐稀疏的 Telegram 服务端分页，每次向界面提供最多 100 个新结果，尚有结果时可点击“加载更多”。例如 500 条结果会分多页取得；遇到不超过 120 秒的 Telegram 限流时显示逐秒倒计时并在同一游标自动重试，长等待或重试次数用尽时保留已有结果和游标，可稍后点击“继续搜索”。

全账号搜索包含会话中对方发送且仍保存在 Telegram 云端、当前账号有权访问的匹配消息。秘密聊天不在 Telegram 云端搜索范围内，已删除、已撤回或当前账号无权访问的服务端历史也无法搜索。程序只在本地保存匹配媒体的必要元数据与消息摘要，不导出或保存整段聊天记录。

相册会按真实会话分别完整补齐，但仍可逐项勾选；同一媒体不会因分页或相册重叠而重复显示。一次全账号选择会生成一个下载任务，文件按各自真实来源名称归档，而不是统一放入“全部会话”目录。加入队列前和数据库提交瞬间都会再次去重，界面会分别报告已加入、重复和不可用数量。搜索历史保存在 `data/database/catalog.sqlite3`，缩略图保存在 `data/cache/thumbnails/`；它们和下载任务数据库相互独立。

设置页的“清理缩略图缓存”只删除缩略图文件，不删除搜索记录或下载文件。删除单条搜索记录或清空当前账号历史时，只清理已无其他记录引用的缩略图。离线启动可以查看已保存历史和结果，但不能刷新会话、发起搜索或加入下载队列。

### 单条消息或相册

粘贴类似 `https://t.me/example/42` 或 `https://t.me/c/123456/99` 的链接，点击“扫描预览”。如果消息属于相册，程序会把同组媒体一起列入预览。用户确认后才创建下载任务。`t.me/c/...` 是私有频道/群组链接，当前登录账号必须已经加入；程序不会自动加入或绕过权限。v0.2.0 会在重启后从账号已有对话中恢复这类私有实体。

### 自动订阅新媒体

打开左侧“自动订阅”，选择当前账号已加入的群组或频道，每行填写一个包含词，并在“包含词关系”中选择“命中任意一个（OR）”或“必须全部命中（AND）”；可另填排除词，命中任意排除词的消息会跳过。每组包含词或排除词最多 20 个。检查间隔支持 5、15、30、60 或 180 分钟，历史补抓可选不补抓或最近 1、3、7、30 天。

默认不补抓历史，新规则会先记录创建时的最新消息作为基线，仅订阅启用后的新消息。启用历史补抓时会固定创建时的消息上界，分批补抓所选范围，再无缝转入增量检查，避免持续到达的新消息使补抓范围漂移。规则支持立即检查、暂停、继续、编辑和删除；删除规则不会删除已经生成的任务或已下载文件。

自动检查仅在程序运行且 Telegram 已连接时执行。每次最多检查 500 条新消息，仍有积压时保存安全游标并在短暂让出前台后继续。手动登录、刷新群组和搜索拥有更高优先级；网络中断时规则会自动退避重试，程序异常退出后会在下次启动恢复。规则、游标和最近运行统计都保存在 `data/database/catalog.sqlite3`，不会创建 Windows 服务、计划任务或额外的系统目录数据。

选中规则后会显示最近 20 次运行，并明确说明本次没有新增任务的原因：没有新消息、未命中关键词、没有所选媒体类型、匹配项均已在队列，或实际新增与重复数量。可点击“只读测试最近 100 条”验证当前关键词和媒体类型；测试最多展示 20 个样本，支持进度与取消。只读测试不会推进订阅游标、创建下载任务、修改规则或写入运行历史，样本仅保存在当前进程内存中。

### 批量导入与频道或群组扫描

点击主窗口的“批量导入”，可每行粘贴一条 `t.me` 链接，也可选择或拖入一个或多个 UTF-8/GB18030 编码的 TXT 文件。一次最多读取 100 条非空链接，TXT 合计不超过 1 MiB。批量预检会报告输入、有效唯一链接、重复链接、无效链接、扫描媒体、任务库重复和空链接数量；失败时保留原输入，确认后把全部有效媒体一次加入一个任务。

单个频道或群组也可按开始日期、结束日期（含当天）、媒体类型和数量上限扫描。筛选在数量限制前执行，结果按从新到旧保留最新匹配项。默认上限为 500，不会无提示抓取全部历史。

### 暂停与恢复

下载中的内容先写入同目录 `.part` 文件。暂停、断网、关闭程序或重启后，会以 `.part` 实际大小作为续传偏移；完成并校验大小后才原子改名为最终文件，同时记录完整文件的 SHA-256。断点续传会先在后台线程读取既有分片建立哈希前缀，不阻塞界面。

扫描失败会在窗口底部持续显示，直到下一条状态替换；已创建任务的失败原因会显示在任务表“错误”列。脱敏运行日志位于 `data/logs/app.log`。如需检查运行时依赖和所有写入位置，可在应用目录执行 `TelegramDownloader.exe --self-test`；报告保存在 `data/logs/self-test.json`，不包含账号、会话或 API 凭据。

### 健康诊断与脱敏诊断包

打开左侧“健康诊断”，点击“开始自检”后，程序会逐项显示进度和结果。检查仅由用户主动触发，不会在打开页面时联网，也不会修改任务、搜索、订阅、下载文件或登录会话。运行中的检查可以取消；已完成项目会保留，尚未执行项目会标记为已取消。

“导出诊断包”会在 `data/diagnostics/` 中生成 ZIP。压缩包严格只包含 `diagnostic-report.json` 和 `diagnostic-summary.txt` 两个文件，只记录固定状态、耗时、布尔值与聚合计数；不会包含应用日志、API 凭据、手机号、二维码、账号、群组、消息、搜索词、文件名、下载路径或数据库原始内容。最近一次结构化结果保存在 `data/diagnostics/latest.json`，同样位于应用目录，不占用 C 盘业务存储。

状态含义：正常表示检查通过；需关注通常表示网络源暂时不可用或尚未配置账号；异常表示路径、空间、组件、数据库、会话或签名验证需要处理；已跳过表示当前没有可检查的可选组件。诊断本身不执行清理或修复，用户可以根据固定说明处理后重新运行。

## 权限与隐私边界

本工具只下载当前登录账号能够正常查看的媒体，不绕过私有频道权限、内容保护、已删除内容或 Telegram 平台限制。请仅下载你有权访问和保存的内容，并遵守 Telegram 条款及所在地法律。

应用不使用系统凭据管理器、默认 QSettings 注册表后端或 Qt WebEngine。Windows 自身可能生成 Prefetch、崩溃记录或安装器短期临时文件，这些不受应用控制；应用配置、缓存、下载和更新状态不会持久放在 C 盘。

## 开发、测试与构建

要求 Python 3.12 x64。以下命令均把虚拟环境、pip 缓存、pytest 临时目录、PyInstaller 缓存和构建产物保存在项目目录：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup-dev.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-installer.ps1
```

基础便携构建输出：

```text
dist/TelegramDownloader/TelegramDownloader.exe
dist/TelegramDownloader-<版本>-win-x64-portable.zip
dist/release/TelegramDownloader-<版本>-win-x64-setup.exe
```

安装器构建会把 Inno Setup 7.0.2 以便携方式放在项目 `.tool-cache` 中，并在使用前核对官方固定 SHA-256 和 Authenticode 发布者；编译、安装及卸载冒烟测试的临时目录和日志都位于 `.build-temp`。安装验收会真实验证 C 盘拒绝、D 盘安装、自检、原位升级、在线更新运行时文件存在，以及普通卸载后用户数据仍保留。

正式发布流程还会生成带版本号的便携 ZIP、安装程序、`update-manifest.json` 与 `update-manifest.sig`。真实 Telegram 登录和下载测试必须由用户在应用内输入自己的凭据完成；测试代码、构建日志和发布资产不得包含这些凭据。

正式发布命令为 `scripts/release/release.ps1 -Version <X.Y.Z>`。它只允许从干净的 `main` 运行，先重跑测试与两种打包冒烟测试，再生成源码归档、规范清单和 Ed25519 签名；随后先创建 GitHub 草稿 Release 与魔搭候选目录，下载两端资产逐字节比对，最后才公开 Release 并推进双方版本指针。GitHub 的源码分支为 `main`；魔搭的 `main` 由平台管理发布资产，源码同步到独立 `source` 分支并使用相同版本标签，避免覆盖历史安装包。发布私钥只允许位于已忽略的 `.release-secrets` 或 CI secret，禁止提交、复制到产物或输出到日志。
